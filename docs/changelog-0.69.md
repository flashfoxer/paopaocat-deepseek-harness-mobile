# 0.69 变更说明

**版本**：`0.0.69+69` · 版本名 `0.69`
**日期**：2026-10-12
**交付形式**：本地 APK（`dist/paopaocat-preview-0.69-arm64-v8a.apk`），**未推仓库**

## 先回答你的问题

> 「是不是每次退出再进日志就会重新开始，要不要先把日志生成改为不进行重置」

**一半猜对了，而且猜到了要害。**

| | 事实 |
|---|---|
| 报告里的 DETAIL | 来自**内存环形缓冲** → **确实每次启动从零开始** |
| 落盘日志 `dsh-diagnostic.log` | **跨启动追加**（只在 512 KB 时轮转一份 `.1`）→ **不重置** |
| 那为什么看不到上次？ | **报告没把它带出来** —— 现场一直在盘上 |

**所以不能改成"不重置"**：那反而会毁掉历史线索 ——
崩之前那几行是**最值钱**的。正确做法是把上一次的尾巴**带进报告**。

这一版就是这个。

## 一、报告新增「上次运行结束前」一节

在 `DiagnosticsLog.init()` 里、**写本次第一行之前**，把落盘日志的尾巴截下来
（上限 **120 行**）—— 此刻文件的末尾正好就是"上次运行结束前"的现场。

报告排版变成：

```
--- KEY（错误与警告…）---
--- 上次运行结束前（最后 120 行；闪退/被杀的开场就在这里）---   ← 新增
0001|…|加载模型：/…/Gemma4.litertlm（backend=gpu, maxNumTokens=32768）
0002|…|已就绪：127.0.0.1:39541（gpu）
0003|…|prompt: 你好                                            ← 崩在这之后
--- DETAIL（最近 N 行，按时间顺序）---
```

放在 KEY 之后、DETAIL 之前：先看"这次运行错在哪"，再看"上次是怎么没的"。
120 行是上限 —— 不截断的话，一份长会话的尾巴能把报告撑成几百 KB。

## 二、报告头部新增「本地模型崩溃记录」

App 从 0.26 起就有一份 `crashes.json`：

```
"Gemma4-E2B|gpu": 3,  "gemma-3-1b-it|cpu": 1
```

它的用途是"崩过就自动换后端"，但**报告里从来没有它** ——
于是"经常闪退"这种反馈**根本对不上账**：哪个模型、哪个后端、崩过几次，
全在盘上，就是没人看得到。现在按次数从多到少列在报告头部。

## 三、刻意**不给结论**

Android 把进程直接杀掉时**没有任何回调**，从 App 侧**分不出**
"正常退出"和"被系统杀掉"。所以这一节只**如实给出最后几行**，
不写"上次崩了"这种没有依据的话。

> 乱下结论比不给证据更坏 —— 那会把排查带偏。

## 四、还没做的（下一版 0.70）

你已同意做、但要求**先把日志这条做掉**，所以这两条排队：

1. **把 LiteRT-LM 引擎挪进独立 Android 进程**（`:llm`）。
   这是"闪退"的**结构性修复** —— 现在引擎跑在 App 自己的进程里，
   引擎一崩（历史真机证据 `code=-11` 段错误）或系统一杀，**整个 App 一起没**。
   llama.cpp 那套是独立进程，所以从来不闪退。
2. **切后台 N 分钟后自动卸载本地模型** —— 降低被系统按内存压力杀掉的概率；
   而且是在你看不到的时候卸载，回来不用等。

**为什么没有在 0.69 一起做完**：这两条要改 Kotlin
（`MainActivity.kt` 1778 行、`LiteRtLmBridge.kt` 1044 行）与 `AndroidManifest.xml`，
而**我这边没有真机可验**。盲改一旦出错，可能是"本地模型完全起不来"——
比现在的"偶发闪退"更坏。所以先用 0.69 把**真实崩溃点**录下来，再动它。

## 五、测试

新增 `test/diagnostics_previous_tail_test.dart` **5 例**：

* 上次的尾巴被截下来，**且真的进了报告**（含崩前那一行）；
* 120 行上限，且截断**保留最后那段**（崩溃点在那头）；
* 第一次跑（还没有落盘日志）不许炸；
* `crashes.json` 读得出来、按次数降序；
* 读不到 / 文件坏了 → 返回空，**不许把报告生成搞挂**。

全量：**656 通过 / 3 跳过 / 0 失败**；i18n **1283 / 1283，0 漂移**。

## 七、你现在该做什么

装上 **0.69**，然后**照常用本地大模型**。等哪次又闪退了：

1. 重开 App；
2. 「设置 → 运行日志」→ 生成报告；
3. 把报告发我。

报告里会多出两样东西：**崩溃前最后 120 行** + **崩溃记录（哪个模型/后端/几次）**。
有了它们我才知道该往哪修 —— 是先修引擎崩溃，还是先解决内存压力。
