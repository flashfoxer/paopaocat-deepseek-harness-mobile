# 「免费大模型」方案（2026-10-13）

## 0. 一句话

**单条通道的伪装路线已经死了**（上游把匿名免费层关了，实测补齐全部已知契约仍 403）。
出路是把它改成 **「多家免费额度 + 自动故障转移」** —— 正大光明用各家公开的免费额度，
一家限流/失效就自动换下一家，界面如实显示每家状态。

---

## 1. 当时复刻的是什么（留个准确记录）

**`FishBottle7/opencode2dsh`** —— 用户 2026-10-11 给的，并定调「仍想要 OpenCode 这条通道，
**设置里显式开启的实验性通道**」。

`app/assets/toolbox/zen-proxy.mjs` 就是照它的实测记录实现的：

- 上游自 2026-09-16 起对非官方会话形状返回 `403 FreeTierError`；
- 它记录的当时门禁只查两件事：① `x-opencode-session` 是 `ses_` + 12 位小写 hex + 14 位 Base62 的**形状**；
  ② 请求体 `stream: true` 且 `tools` 里有名为 **`bash`** 与 **`read`** 的函数工具。
- 它另带一个**可选的 IP 池**（设置页里的 `multi-exit rotation`）来分摊**按出口 IP 的配额** ——
  我们**刻意没实现**，理由见 §5。
- 它的重试是**有界退避**：`8 次重试，~1s→20s 退避，单步最坏约 90s`，并且**静默熬过去**
  （它的取舍）。我们没做重试、选择**如实报错**：更透明，但体验略差 ——
  **这一条我可以补成「小步退避 + 换源」**。

## 2. 现在的实测结论（2026-10-13，本机直连）

| 请求 | 结果 |
|---|---|
| `stream:false` + 只有 `read` | 403 FreeTierError |
| **`stream:true` + `bash` + `read`（完全照门禁记录）** | **403 FreeTierError** |
| `stream:true` + 无 `tools` | 403 FreeTierError |

三行都带齐了 CLI 伪装头（UA `opencode/1.18.31`、`x-opencode-client: cli`、`x-opencode-project`、
形状正确的 `x-opencode-session`）。**结论：门禁已不在请求里。**

旁证两条：① 社区插件 `viztor/dsh-opencode-patch` 的 README 自己写着「the gate is not in the request, measured」，
并说要用**一个凭据**（登录或 Zen/Go Key）才稳；② 2026-08-27 那次排查已实测 **OpenCode Zen 对大陆 IP
本身就是地区封锁**（`403 RegionError`）。所以这条路对国内网络**本来就不稳**。

用户手机上的原话（v0.73 报告）：`[zen-proxy] 上游 HTTP 403：FreeTierError: ...` —— App 的报错文案是对的
（如实说"上游拒绝了、可能又收紧了"，并给"等它恢复 / 先关掉换别的模型"两条路）。

## 2.1 最新解法（2026-10-13 实测通过，通道可以救活）

**先说结论：这条路今天能修，而且我们已经修好并实测通过了。**

排查链路（每一步都有取证）：

1. `opencode2dsh` 的最新版是 **v0.3.11（10-11）**，它解决的是 **10-10 那次**变动
   （通道搬到 `/inference`、要求 `bash`/`read` 工具、`Bearer public` 会被 401）——**不是今天这次** ✗；
2. 它自己的 issue **#62（10-13 当天新开）** 里，用户报的故障和我们一模一样（"API 密钥无效"/403
   `FreeTierError`），有人指向跨项目的同源故障 **`decolua/9router#4780`**；
3. 那份 issue 把真因写清了：**上游开始校验会话 id 的前 12 位 hex 能不能解码成合理的时间戳**
   （真客户端编码 `~(BigInt(Date.now()) * 0x1000n + counter)` 取低 48 位）。各家复刻实现
   （含我们）都是把种子 **sha256 派生**出这 12 位 ✗ → 一律被判成"不是 OpenCode 客户端" → 403。
   形状早就对了，**语义**不对。

**本机复核（不是照抄）**：curl/HTTP2 + 今天在售的免费模型（`big-pickle`）+ 旧的摘要派生 id → 403；
换成时间戳编码的 id → **200 且真流式吐字**。`Authorization: Bearer public` 可带可不带；
`tools` 里的 `bash`+`read` 仍然必需（缺了 403）。

**改动**：`canonicalSessionId()` 里那 12 位改为时间戳编码（基准按天取整 → 同一天内同一会话
拿到同一个 id，保住 prompt-cache 亲和；上游不校验会话新旧，实测 30 天前的照样 200）。

**验证（对真正出货的产物做的端到端）**：

| 项 | 结果 |
|---|---|
| 补过之后的代理，端到端发一次对话 | **HTTP 200**，10,824 / 10,273 字节真 SSE，模型真回了内容 |
| 同一 seed 两次 | **完全相同的会话 id** ✓（缓存亲和没丢） |
| 不同 seed | 不同的会话 id ✓ |
| 形状 | 全部匹配 `ses_` + 12 位 hex + 14 位 Base62 ✓ |
| 用本地回声服务器抓真实外发请求 | `Bearer public` + `tools=[bash,read]` + 时间戳 id ✓ |

**⚠️ 但请把它当"临时救活"，不是"修好了"**：这是 4 天内**第 4 次**上游变动
（09-17、10-09/10-10、10-11、10-13）。每一次都得重新逆向 + 改代码 + 重发包。
所以 §3 的多源方案**仍然要做** —— 它的价值恰恰是"不用跟着单条通道的变脸跑"。

## 2.2 第 5 次变动（2026-10-13/14）与我们的修复（2026-10-15）

**先说一句**：§2.1 那次（10-13 的时间戳会话 id）**当时确实修好了** —— 实测 200 + 真流式吐字。
但那份文档自己也写着"**把它当临时救活，不是修好了**：这是 4 天内第 4 次变动"。
现在就是**第 5 次**。

**这次换了四处（社区用自签 CA 中间人抓官方 1.19.0 客户端的真实请求 + 逐字节重放测出来的）**

| 项目 | 现在要求 | 不满足时 |
|---|---|---|
| 端点 | **`/inference/v1/chat/completions`**（老 `/zen/v1/...` 直接关门） | 无条件 403 |
| 会话头 | **`x-opencode-session-id` 必须存在**（值同 `x-opencode-session`） | 403 |
| 工具指纹 | `bash` 与 `read` **同时**声明，且**各自 schema 至少一个 property** | 只其一 / `properties: {}` → 403 |
| UA | 含 **`deepseek-harness`** 一律 403 | 403 |
| 遗留头 | **`x-session-affinity` / `x-session-id` 不能发**（多发 = 非官方信号） | 403 |

来源（都是 2026-10-15 当天）：`LAGcomcom/zen-gate#62`、`MingLoong/Aether#71`+`#72`、
`luqman-v1/9router-go#322`、`Ebony-Vinyl/dsh-our-free-model#330`、`6Kmfi6HP/opencode2api#48`。
其中 **`dsh-our-free-model` PR#330** 与我们是同一个用法（中文 / Node / 免密车道），
它的 `docs/free-lane-wire.md` 就是上面那张表。

**我们做了什么**：`zen-proxy.mjs` 的基址改成 `https://opencode.ai/inference`、去掉两条遗留头、
补 `x-opencode-session-id`、诱饵工具与调用方自带的 `bash`/`read` 都保证"至少一个 property"、
UA 加 `deepseek-harness` → `dsh` 的净化；403 在 App 里**专翻一条**文案
（说清"不是你没配 Key"，并给"换一个自己配了 Key 的模型"这一步）。

**验证与边界（如实写）**：

* `node install/test-zen-proxy.mjs` → 13 项全过（本地假上游；断言钉住了路径常量、
  会话头、两条遗留头必须缺席、工具 schema 必须有 property）。
* ⚠️ **本机（服务器出口）实测仍然 403**：按新契约做了 6 组变体（三种工具集 × 有/无
  `x-opencode-request`，走 node:https 的 HTTP/1.1）全部 403；而社区在各自机器上同样形状拿到 200。
  所以**要么上游又加了 v3，要么是出口 IP 被分桶** —— 这一条只能由**真机**判定
  （手机是住宅 IP，跟服务器出口不是一回事）。

**⚠️ 结论没变，而且更硬了**：单条通道的"跟着变脸跑"路线**不可持续**（5 次变动，一次比一次快）。
§3 的多源池仍然是正解；在那之前，**别把它设成出厂默认**。

## 3. 方案：多源免费池 + 自动故障转移

### 3.1 池子分三层（按"要不要注册"）

| 层 | 源 | Key | 限额 | 大陆直连 |
|---|---|---|---|---|
| **L1 零配置** | OVHcloud AI Endpoints | 免注册免 Key | 2 次/分钟/IP | ✓（8-27 实测可用） |
| **L2 主力（注册即得）** | 智谱 bigmodel `glm-4.6v-flash` | 要（免费注册） | 永久免费 | ✓ |
| L2 | 阿里云百炼 DashScope | 要 | 每模型系列 100 万 token / 90 天 | ✓ |
| L2 | 硅基流动 SiliconFlow | 要 | 新用户 ¥14 赠金 | ✓ |
| L3 可选（默认关） | Groq / Cerebras / Cloudflare Workers AI / OpenRouter 免费档 | 要 | 各家免费档 | ✗ 需代理 |

### 3.2 机制（复用 App 里**已有**的「轮换池」基础设施）

1. 每个源一份**健康状态**：最近成功/失败时间、上次失败原因、今日用量；
2. 失败（429 / 5xx / 403 / 超时）**自动换下一个**（现有粘性 lastGood 逻辑照搬）；
3. 启动时**可选**做一次极轻的探测（每源 1 次，不循环、不重试轰炸）；
4. 界面**如实显示**每个源的状态与余额，并说明为什么跳过它（绝不假装成功）；
5. 全部源不可用时**明确报错 + 给下一步**（这一条现在就已经做对了）。

### 3.3 模型清单（目录）怎么更新

内置一份 JSON（随包）+ **可选**从仓库 raw 拉最新
（`raw.githubusercontent.com` 本机实测可达；带版本号 + sha256 校验）。
这样上游一变，**改一次 JSON 就能让所有人受益**，不用重发版 ——
就是 FreeLLMAPI 那条「签名 feed」的轻量版。

### 3.4 要改的代码（都在 `dsh-mobile` 里，可控）

| 文件 | 改动 |
|---|---|
| `app/assets/toolbox/zen-proxy.mjs` | 重写为 `free-pool-proxy.mjs`：多上游 + 健康状态 + 故障转移 |
| `app/lib/local/zen_proxy.dart` | 改名 `free_pool_proxy.dart`，加状态读取 |
| `app/lib/ui/pages/settings_tab.dart` | 「免费模型（无需 Key）」→「免费额度模型」：列源 + 状态 + 填 Key 入口 |
| 预设厂家 | 智谱 / 百炼 / 硅基流动 做**一键填充**（只需粘 Key） |
| i18n / 测试 / 台账 / 使用说明 | 同步 |

## 5. 需要用户拍板

1. 至少注册一个免费源（**推荐智谱**，5 分钟、永久免费）；或明确「只用 OVH 那个免注册的」
   （2 次/分钟，只够试玩）。
2. 先做 B、还是 B+A 一起。
### 5.1 为什么不做 IP 池（多出口轮换）

1. **手机端没有这个基础设施**：代理跑在**用户手机**里，而"IP 池"意味着流量要经过**一批代理出口** ——
   要把这条路做出来，得**用户自己买/搭代理**并配到手机上（普通用户做不到）；
   没有真实出口的"IP 池"就是个摆设。
2. **它对付不了今天这类问题**：今天挂掉的原因是**按客户端识别（403 FreeTierError）**与
   **地区封锁（403 RegionError）**，而不是"按 IP 的配额" —— IP 池只分担后者。
   也就是说：**当初就算做了，今天照样死**。
3. **风险落在用户自己的出口**：按 IP 的封禁封的是**用户家/手机的出口**，不是我们的。
4. 所以这里的选择是：**换源**（一家不行换一家，而且是各家的**公开免费额度**），
   而不是**伪装 + 多出口规避**同一个源。

3. **产品口径**：把卖点从「**不用填 Key**」改成「**注册一次、永久免费**」——
   这才是能长期兑现的承诺（今天的坏消息正好证明「零 Key」不可持续）。
