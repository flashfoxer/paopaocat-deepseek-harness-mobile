# 泡泡猫 DSH 手机版 v0.61 · 更新说明

> 本版修的是你 2026-10-11 报的**第二批 7 条**：打开落在影视页、本地服务没起来
> 只说一半、短剧按钮被挤出屏幕、本地大模型页窄屏挤出、知识库到底有没有用、
> 图像/视频模型能不能加外部厂商、特殊权限点不开也看不懂。

## 1. 打开 App 就是首页
- 以前会**恢复你上次停留的那一页**（例如影视）。覆盖安装后一打开就落在影视页，
  看着像「首页没了」。
- 现在：只有 App 还在后台、被系统重建时（同一次运行）才恢复页面；
  **重新打开一律回首页**。

## 2. 「本地服务没起来」现在会告诉你为什么
- 以前只有这一句，要自己去「运行日志」里翻。
- 现在直接带上**真正的原因**：还没装模型 / 引擎刚崩了 / 被系统回收了 / 端口被占……
  并按原因给下一步（例如「回这一页点一次启动」）。
- **顺着这条又查出一个真缺口（用户 2026-10-11 追问「修复了没有」时查出来的）**：
  `litert-lm`（Gemma 4 的 `.litertlm`）走的是**另一条启动路径**，而那条路
  **一处都没写失败原因** —— llama.cpp 那条路每一处都写了（引擎文件不在 / 模型文件不在 /
  端口都试过 / 进程退出），这条漏了。于是这类模型起不来时，`lastError` 是 null，
  界面只能显示那句「本地服务没起来（详见运行日志）」——**用户看到的就是这句**。
  - 现在补上：原生层那句原话（缺哪个 `.so` / `OutOfMemoryError` / 模型文件不对）
    会原样带到界面上；GPU 起不来自动改用 CPU、两条都不行时**两段原因都在**
    （否则用户会以为"换了 CPU 还是同样的错"）。
  - 抽成纯函数 `LocalModelServer.litertStartReason` + 新增
    `test/local_model_start_reason_test.dart`（6 条）钉住
    「**每种失败形态都必须给出一句有信息量的人话，不许是空串**」——
    这个 bug 的形态就是"少写一行赋值"，编译期和运行期都不会报错。
- ⚠️ **说清边界**：本机没有安卓设备、LiteRT-LM 引擎也跑不起来，所以
  **"到底为什么起不来"只有你手机上的运行日志能回答**。这一版保证的是
  "失败时原因一定会显示出来"，不是"启动问题已解决"。

## 3. 影视页六个入口全部看得见
- 「短剧」以前被挤出屏幕右边（那排入口是横向滚动的，入口从 5 个变 6 个之后开始挤）。
- 现在改成**自动换行**：生图 / 生视频 / 修图 / 口播 / 短剧 / 作品
  在任何宽度的手机上都在屏幕里。

## 4. 「本地大模型」页在窄屏上不再被挤出去
- 底部导航那 6 个入口、页面里几处固定宽度的行都按窄屏重排过。
- 新增**窄屏回归测试**：320 / 360 / 392 dp 三种宽度各渲染一遍，
  一旦出现「挤出屏幕」（RenderFlex overflow）就直接**测试失败** —— 以后改版不会再悄悄坏掉。

## 5. 知识库在本地对话里确实是生效的（补了证据）
- 这条链上有三段（建索引 / 检索 → 拼上下文 → 发请求），**每段各自都有测试**，
  但「它们到底接没接上」以前**没有证据** —— 中间任何一段忘了传都不会报错，
  表现只是「回答没用到知识库」。
- 现在补了一条**端到端测试**：真建索引、真检索、真发请求，断言**资料原文确实出现在
  发给引擎的请求正文里**（同时钉住「一条 system 消息都不许有」这条简单对话的定义）。
- 口径：这证明的是 **App 把资料送到了引擎手里**，不是「模型一定会照资料回答」
  （那是模型行为，App 保证不了）。
- 顺带修好这一轮排查发现的两个知识库问题：
  1. **下载校验失败时残留的半个文件会让这个包永远装不上**：换源续传会拿
     「坏开头 + 好尾巴」拼在一起，怎么校验都不过，界面只会重复同一条校验错误。
     现在**校验失败会丢掉重下**；传输中断仍然保留 `.part` 继续续传（不白下几百 MB）。
     另外 `.part` 比目标还长时以前会卡死（直接 return → 校验必然失败 → 又 return），
     现在会丢掉重下。两条都有回归测试（`test/kb_download_test.dart`）。
  2. 知识库页那句「装了知识库还不会改变模型的回答」是**过时的**
     （0.56 起就已经会自动检索）。现在改成如实说明：装完要点「建索引」，
     建过索引的包提问时会自动查（每包最多 2 段、总共最多 3 段），
     **查到不等于模型一定照它回答**，资料没命中时一句都不会发出去。

## 6. 「图像 / 视频模型」添加模型时内置了外部厂商端点
- 点「添加一个模型」时，图像那一边多了一排**内置厂商**：
  **OpenAI / 智谱 GLM / 通义万相（阿里云）/ 豆包 Seedream（火山方舟）/ MiniMax /
  硅基流动 SiliconFlow** —— 点一下自动填好**端点、建议模型名、厂家 id**，
  你只要在「云端大模型」里配好那家的 Key（厂家 id 要对得上，界面会提示）。
- ⚠️ 如实说明：本 App 的图像请求是**按 Agnes 的形状发的**
  （`size` 用 1K/2K 档位、参考图与 `response_format` 放 `extra_body`），
  多数第三方端点不认这两样 —— **能不能通要试**，失败会把上游原话显示出来。
- ⚠️ **视频没有内置外部厂商**：本 App 的视频请求只认 Agnes 那套形状
  （`POST /videos` + `agnesapi` 轮询），换别家基本不通。这一点在添加视频模型时
  界面上直接写明，不给你"看着像内置好了、其实必然失败"的假绿灯。

## 7. 「去水印」改名「擦除」，框可以自己在图上拖
- 以前只能从几个**预设位置**里挑；水印不在那几个角上就没法对准。
- 现在：**按住预览图上的红框直接拖**到要去掉的东西上面，拖动**即时响应**
  （按图像像素 / 显示像素换算，拖到边界后反向拖也立刻跟手）。
  下面那几个位置按钮变成**「起点」**，点一下把框放回那个角。
- 名字也按你的口径改成**「擦除（去水印 / 去杂物）」** —— 它能擦的不只是水印。

## 8. 「手机权限」里的特殊权限修好了
- **根因**：这 5 项（全部文件访问 / 悬浮窗 / 修改系统设置 / 使用情况访问 /
  安装未知应用）**一条都没在应用清单里声明**。没声明的特殊权限，
  系统设置页里本应用的开关就是**灰的或根本不出现** —— 这就是「点开以后无法点选」。
  现在 5 条都已声明；打不开"专属页"时还会**自动退到不带包名的全局页**
  （国产 ROM 常把入口改名、藏起来或整个删掉）。
- 界面从「一排只有名字的按钮」改成**列表**，每项写清：
  **一句人话用途** + **在系统里的手动路径** + 「不给也能用吗」。
  例：「使用情况访问」= 看哪个应用在用、用了多久；⚠️ **没有"只看本应用"的页面**，
  是一份应用列表要自己找。
- ⚠️ 这一页**不显示这 5 项的实时状态**：Android 只在系统页面里读/改它们，
  要在这里显示得再加一个原生查询接口（这版没做，界面里如实写了）。
  是否已开启，以系统页面里的开关为准。
