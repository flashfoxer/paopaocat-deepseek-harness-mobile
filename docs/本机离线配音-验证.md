# 本机离线配音（sherpa-onnx + 中文 VITS）验证记录

> 日期：2026-10-13 ｜ 目的：用户提「系统配音没有本机可用的吗，给一个方案」，
> 定的方案是 **B（集成 sherpa-onnx 做本机离线配音）+ A（配音失败也照样出片）**。
> 这份记录是 **B 的"先验证再承诺"**：先在能跑的环境里把中文合成真跑通、量出真实数字，
> 再决定要不要进包。**样音在 `samples/`**，音色好不好听由用户听，不由我替他说。

## 一、结论（先看这个）

| 项 | 实测值 |
|---|---|
| 神经模型 `model.onnx` | **29.07 MB** |
| 词典 + tokens + 4 个小 fst | **约 2.6 MB** |
| **模型侧合计** | **约 31.7 MB**（**172 MB 的 `rule.far` 不需要** —— 见第四节） |
| Android arm64 原生库（3 个 .so） | **25.93 MB**（其中 `libonnxruntime.so` 21.22 MB） |
| 原生库压缩后（进 APK 的那部分） | tar.bz2 10.47 MB |
| **设备总占用** | **约 58 MB**（模型 31.7 + 原生 25.9） |
| 合成速度（**x86 桌面**，2 线程，含模型加载） | 10 秒中文 ≈ **0.9 s**（够用） |
| 模型加载（每进程一次） | **0.38–0.49 s**（App 里只加载一次，之后常驻） |
| 净合成实时率（桌面，约等于不含加载） | **约 17–20×** |
| 手机（arm64）速度 | **未实测** —— 桌面 x86 只能作参考，真机必须自己量 |

## 二、怎么拿到的（可复现）

```bash
# ① 运行时：官方 Flutter 包（pub.dev 可达），按 ABI 拆分，只取 arm64
#    sherpa_onnx_android_arm64 1.13.8 → android/src/main/jniLibs/arm64-v8a/*.so
# ② 桌面验证用官方 Linux 预编译包（GitHub 发布资源可达）
#    sherpa-onnx-v1.13.8-linux-x64-shared.tar.bz2（26.9 MB，**自带 libonnxruntime.so**）
# ③ 中文模型（sherpa-onnx 官方 Android TTS 示例用的那个，int8 多说话人）
#    vits-icefall-zh-aishell3.tar.bz2（31.5 MB 下载 → 解包 204 MB）
export LD_LIBRARY_PATH=<解包目录>/lib
<解包目录>/bin/sherpa-onnx-offline-tts \
  --vits-model=.../model.onnx --vits-lexicon=.../lexicon.txt --vits-tokens=.../tokens.txt \
  --num-threads=2 --sid=0 --output-filename=out.wav "要念的中文"
```

## 三、网络可达性（本机实测，很反直觉，记下来省得再试）

| 站点 | 结果 | 用途 |
|---|---|---|
| `github.com`（网页 / releases 页面） | ✗ 超时 | 打不开仓库页 |
| **GitHub 发布资源**（`/releases/download/...` → `release-assets.githubusercontent.com`） | **✓ 206** | **模型与预编译包就是这么下下来的** |
| `raw.githubusercontent.com` | ✓ 200 | 取仓库里的文件 |
| `codeload.github.com` | ✓ 301 | 取仓库 tarball |
| `pub.dev` / `pub.flutter-io.cn` | ✓ 200 / 301 | 拿 Flutter 包（`sherpa_onnx_android_arm64`） |
| `pypi.org`、`files.pythonhosted.org`、`pypi.tuna.tsinghua.edu.cn` | ✓ | Python 侧的轮子 |
| `huggingface.co`、`hf-mirror.com` | ✗ 超时 | 用不了 HF 的模型 |
| `modelscope.cn` | ✓ | 可用，但**没找到** sherpa-onnx 的 ONNX TTS 模型（那个官方中文 TTS 仓库是 PyTorch 权重） |

⚠️ 另外两个坑：① 本机**没有 pip**（`python3 -m venv` 与 `ensurepip` 都缺），
所以 Python 侧只能"直接从 PyPI 下 wheel、当 ZIP 解压、用 `PYTHONPATH`+`LD_LIBRARY_PATH` 跑"；
② sherpa-onnx 1.13.8 的 Python 绑定需要 `onnxruntime` 的符号版本 **`VERS_1.28.2`**，
而 PyPI 上只有 1.28.0 / 1.29.0 / 1.31.0 → **对不上**，所以桌面验证最终走的是
**官方 Linux 预编译包（自带 ORT）**，不是 pip 那条路。

## 四、`rule.far`（172 MB）为什么可以不要

带数字与日期的一句话：`今天是2026年10月13日，某只股票涨了3.14个百分点，成交量是12万手。`

| 配置 | 音频时长 | 合成耗时 | 判断 |
|---|---|---|---|
| 只给 model+lexicon+tokens（**最小**） | 7.57 s | 0.59 s | 数字读法最"省"，可能读得含糊 |
| **加 4 个小 fst（date/number/phone/new_heteronym，约 0.25 MB）** | **13.32 s** | 0.83 s | 展开最充分（把数字读成汉字），**推荐** |
| 加 `rule.far`（**172 MB**） | 6.50 s | 2.74 s | 体积大、加载慢，且读得**更短**，没有收益 |

结论：**随包 4 个小 fst，不要 rule.far** —— 设备占用从 204 MB 降到约 32 MB。
（音色与"3.14 读成三点一四"这类细节，最终要**用户听**：样音 2 就是这一句。）

## 五、还没验的（如实列）

1. **手机上的真实速度与内存**：桌面 x86 的 17–20× 不能直接搬到 arm64；
   真机要量"一句 10 秒的话要几秒"。
2. **长时间使用的内存**：模型常驻约 30 MB 权重 + onnxruntime 运行时，真机要看峰值。
3. **音色是否可接受**：VITS int8 的多说话人模型（174 个说话人）机械感通常强于云端 TTS
   （MiMo / MiniMax）。**这是产品取舍，得用户听**（`samples/` 三个样音）。
4. **模型许可**：`vits-icefall-zh-aishell3` 出自 icefall（Apache-2.0）与 aishell3 数据集，
   进包前要把许可写进"关于 → 第三方组件与许可"，并把模型来源标清。
