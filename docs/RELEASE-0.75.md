# 泡泡猫 DSH 手机版 v0.75

**本版三件事：① 设置页能「检查更新」 ② 查到就能在应用内下载、验完哈希与签名再交给系统安装
③ 安装包瘦身（更新时的流量少 32 MB）。**

> 体积口径：下面用 **MiB（1024 进制）**，也就是 App 里显示的那个数；括号里是十进制。

---

## ⬇️ 先看这里：该下哪个包

| 你的情况 | 下载哪个 |
|---|---|
| **全新安装**（没装过，或清过应用数据） | **`paopaocat-preview-0.75-arm64-v8a.apk`（完整包，95.2 MiB / 99.8 MB）** —— 装完即用，**手机没网也能打开** |
| **已经装过旧版** | 不用手动下：App → 设置 →「检查更新」，它会自动下 **`…-lite.apk`（精简包，65.1 MiB / 68.3 MB，省 32 MB）** |

两个包的 **versionCode 与签名完全相同**（`75` / `7aaf4448…d3cc17`），可以互相覆盖安装。

> 第三个附件 `dsh-runtime.zip`（32 MB）是"装了精简包、但手机里还没有运行环境"时的兜底，普通用户不用管。

## 一、这一版修掉的一个硬伤（先说这个）

0.75 最早**只发了精简包**。那只适合"更新"：老用户手机里早就有那份 32 MB 的依赖树，
再下一遍是浪费。**但全新安装 + 手机没网 = 连界面都进不去** —— 这不是"少个功能"，是打不开。

> 这个硬伤是用户 2026-10-14 指出来的：「初始包变小了，用户首次安装可以在线下载其他的依赖包，
> 但是如果用户手机网络连不上，那么软件就不能用了」—— 说得对，而且后果比字面更重。

**修法不是回滚，而是出两种包、各用各的场合**：

| | 体积 | 给谁 | 包里带运行时？ |
|---|---|---|---|
| 完整包 `…arm64-v8a.apk` | **95.2 MiB** | 全新安装 | ✅ 带（装完即用、无网也能打开） |
| 精简包 `…arm64-v8a-lite.apk` | **65.1 MiB** | 应用内更新 | ❌ 不带（手机里已经有了） |

**App 自己判断该下哪个**：`isRuntimeReady()` 为真（手机里有运行时）→ 下精简包；
为假（新装 / 清了数据）→ 下完整包。判断只在**一处**做（`UpdateInfo.pickVariant`），
界面不自己拼 URL —— 免得出现"按精简包显示体积、实际下了完整包"这种对不上账的事。

构建上是一个环境变量：`DSH_ANDROID_INCLUDE_RUNTIME=1` 出完整包，不设出精简包。

**附带的好处**：完整包（95.2 MiB）比 0.74 的 106.3 MiB **还小 11 MB** —— 那是本地大模型那一套被拿掉的结果。

## 二、检查更新（设置页第一块，默认展开）

「我知道有没有新版」以前只能靠我发消息告诉你。现在 App 自己去更新源读一份版本清单：
有新版本就显示**版本号、发布日期、包多大、这一版改了什么**。

* **静默**：启动后在后台查一次；三条源依次回退（GitHub 原站 → jsDelivr → 你自填的镜像）。
  全都不通就只写一条日志，界面上如实说"这次没查到"并给出**每一步卡在哪**（想看可以展开）。
  **不弹窗、不挡启动** —— 这类检查最容易变成"每次开机弹一个查不到更新的框"。
* **可关**：设置里能关掉自动检查，那时只有你点按钮才会联网。
* **更新源可自填**：国内直连 GitHub 时好时坏；填错格式当场提示，点「恢复内置源」回到默认。
* **「跳过这个版本」**：只跳过这一版，出了下一版照样会告诉你。

## 三、应用内下载 + 双校验 + 交给系统安装

点「下载到本机」之后的完整链路：

1. **下载**：支持**断点续传**（中断了下次接着下，不用重头来），有进度、速度、可取消。
   文件名会先洗一遍（清单来自网络，防路径穿越），体积上限 2 GB（清单被改成指向大文件时早停）。
   下载区会**提前写清这次下的是哪个包**（精简 / 完整、多大）。
2. **校验两样**：
   * **文件哈希** —— 没下坏；
   * **签名** —— 与**当前已装应用**比对（`getPackageArchiveInfo` 读包，与自身签名比）。
     **对不上就不给你装**，这是"更新包被人换成别的"的唯一防线。
     读不出签名、包里没签名、读包失败，**一律判不通过**（拿不到结论 ≠ 可以装）。
3. **安装**：`ACTION_VIEW` + `application/vnd.android.package-archive` + FileProvider
   （`file_paths.xml` 只开了 `updates/` 这一层，没开整个私有目录）。
   差权限时带你去系统的「安装未知应用」页，回来再点。

### 必须说清的边界

* **最后那一下一定要你亲手点**：Android 不允许普通应用静默安装（任何正规 App 都一样）。
* **装没装成，我们也看不到** —— 界面上**不会**编一句"安装成功"出来。
* 签名不一致时**唯一**的办法是卸载重装（数据会丢）—— 界面会把这句原话说出来。

## 四、瘦身的两块来源

1. **本地大模型那一套（LiteRT-LM，11 MB）整个不进包** —— 你 0.70 就把入口撤了，却一直占着 11 MB。
   只排除了四个 `.so`（推理本体 + GPU/NPU 加速器）；**Java 类与 `LiteRtLmBridge.kt` 都留着**
   —— 要恢复只需删掉 `build.gradle.kts` 里那四行 `excludes`，不用改任何代码。
   真走到那条路时拿到的是 `UnsatisfiedLinkError`（已被 `catch Throwable` 兜住），不是崩溃。
2. **运行环境只在"更新"时不下**（就是上面那 32 MB）。⚠️ 但**新装必须拿完整包** —— 见第一节。

还想再小吗？剩下的 65 MB 里，`libnode.so`＋ICU（29 MB）与 `libflutter/libapp`（9 MB）是硬成本；
ffmpeg（10.5 MB，剪辑/修图）与 ONNX/sherpa（9.4 MB，离线配音）都是在用的功能 ——
**要到 50 MB 以下必须砍掉在用的功能**（或重新编译 node 用 small-icu）。

### 顺带纠正一句我之前说错的

上一轮我说"本机 Kotlin 编译卡死、判定为环境问题" —— **真因是我漏了 `GRADLE_USER_HOME=/tmp/gradle-home`**
（项目 `docs/BUILD-LINUX.md` 早写明），结果用了空缓存一直在静默下载依赖。
按文档姿势跑：**出包只要 114 秒**，而且 `assembleRelease` 顺手把 L2 的原生代码也验证了。

## 怎么升级

* **应用内**：设置页 →「检查更新」→「下载到本机」→ 等它验完 →「安装」→ 在系统界面上点「安装」。
  覆盖安装，**数据不会丢**。
* **手动**：下载本页的 APK 点开安装（同一把签名，可覆盖）。

## 没做 / 还没验的

* **没有真机验证**：① 全新安装装完整包后能不能正常解压运行环境并打开；② 排除 LiteRT 的 `.so`
  之后 App 能否正常启动；③ 应用内"下载 → 校验 → 安装"整条链。都需要装到设备上走一遍。
* **应用内下载依赖 GitHub 可达性**：仓库与 Release 都在 GitHub，国内手机直连不稳时可能失败
  （镜像只能救清单、救不了包 —— 实测 jsDelivr 不代理 Release 附件）。退路是「改用浏览器下载」。
* **没有静默安装、没有自动安装**：这是 Android 的规则，不是取舍。
