## 1. 先看一个结构性问题：**被测的东西和交付的东西不是同一个**（P0-1）

这是本次审计最重的一条，因为它解释了一连串「测试全绿但真机坏」。

**实测（✅复算，我亲自拆的包）**：

```
dist/paopaocat-preview-0.57-arm64-v8a.apk → lib/arm64-v8a/libapp.so (7.9 MB)
  assets/toolbox/open-app.mjs        出现 0 次   ← 就是它
  assets/toolbox/make-pptx.mjs       出现 1 次
  assets/toolbox/vision-proxy.mjs    出现 1 次
  assets/toolbox/make-image.mjs      出现 1 次
```

字符串确实会被编进包（其余 6 条都在），**只有 open-app 那一条不在** → 装到手机上
`files/toolbox/open-app.mjs` 永远不会被写出，而技能文件写着「只有这一条路」。真机后果
（报告 2026-10-09 17:34–17:47）：模型自己绕 **14 分钟**，最后把一轮 prompt 拖到
`TimeoutException: ACP 请求超时`。

时序（✅复算）：

| 时间 | 事件 |
|---|---|
| 09:17 | 0.57 出包（`dist/paopaocat-preview-0.57-...apk`） |
| 09:58 | 提交 `53db4b5` 才补上这一行 |
| — | 273 条测试全程全绿；出包脚本里跑 `flutter analyze\|test` 的次数：**0 次** |

**结论**：这不是「某个功能有 bug」，而是**流程缺口**——测试只跑 Dart 源码；资产类测试读的是
工作区文件（`File('assets/...')`）而不是包内文件；出包脚本不跑闸；出完包没有任何核对。

**建议**：一个出包后脚本（python + zipfile，约 20 行）：
1. 解 APK，核对 `assets/flutter_assets/assets/{toolbox,skills,kb,models}` 与仓库逐名一致；
2. 在 `lib/arm64-v8a/libapp.so` 里核对 `AndroidToolbox.assets` **每一条 key** 都存在；
3. 核对 APK 的 `versionName == kAppVersion`。
挂到 `install/rebuild-and-verify.ps1` 出包之后。这一条同时能挡住 `pubspec` 漏声明资产
（历史上翻过车，注释里写着「APK 里一条技能都没有」）与「改了源码却打了旧包」。

## 2. P0 其余三条

### P0-2 模型（及它读到的任何不可信文本）能拿到用户全部 API Key ✅复算

- `app/assets/toolbox/android-exec-shim.cjs:285-301`：`parentEnvBase()` 默认**全量继承
  `process.env`**；同文件 280-281 行注释自认「不设（默认）→ 全量继承 process.env」。
- **全仓没有任何地方设置** `DSH_ANDROID_ENV_PASSTHROUGH`（✅复算：`grep` 零命中）——
  也即白名单开关**已实现但从未启用**。
- `app/lib/local/dsh_runtime.dart:519` 把 `...apiKeys` 注入 node 进程 env；`:494-497` 注入
  `DSH_DEVICE_TOKEN`。
- 审计员在 `/tmp` 实测（加载仓库那份 shim）：子进程 env 里出现
  `DEEPSEEK_API_KEY / AGNES_API_KEY / DSH_DEVICE_TOKEN`，且值能到达 shell。
- 第二条独立路径：轮换组把真 Key 明文写进 `<filesDir>/toolbox/rotate-config.json`
  （`rotation_proxy.dart:110-119,153-159,186-190`），而 `HOME=filesDir`
  （`dsh_runtime.dart:483`）→ `cat $HOME/toolbox/rotate-config.json` 即可。

**风险场景（具体）**：用户把一份网上下载的文档或知识库包交给 Agent（都属不可信文本），
其中一句「顺便执行 …`process.env.DEEPSEEK_API_KEY`…」就能把 Key 带出手机。
App 自己的注释（`dsh_runtime.dart:723-725`）写着边界是「模型碰不到其它应用的数据，
也出不了 App 私有目录之外」——数据确实出不去，但**凭据可以出网**，声明与实现不符。

**建议**：设 `DSH_ANDROID_ENV_PASSTHROUGH=AGNES_,LOCAL_,DSH_ANDROID_`（开关已存在）；
rotate-config.json 不经文件传 Key（改 stdin）；按调用点只下发必需的变量。

### P0-3 轮换代理 `127.0.0.1:39321-39330` 无任何客户端鉴权（审计员实测）

- `app/assets/toolbox/rotate-proxy.mjs:719` `server.listen(port, '127.0.0.1')`；
  全文无 `401/403/unauthorized` 分支；端口是常量（`dsh_runtime.dart:462`）。
- 「loopback 整机共享」是本仓库自己的论断（`device_bridge.dart:18-19`）——设备通道为此
  加了随机令牌，**代理没有**。
- 风险：同机任意带 INTERNET 的应用扫这几个端口 → `POST /v1/chat/completions`
  → **用用户的 Key 花钱**，响应明文可读。浏览器因无 CORS 读不到响应，但可盲发消耗额度。
- 建议：照抄设备通道那套（启动随机令牌 → 交给 DSH → 代理校验）；端口也改随机。

### P0-4 知识库下载器零测试，且完整性只看字节数（测试审计 ✅数字复算）

- `lib/local/kb_store.dart:274-393` 是本仓库最大的网络 IO（清单里那包
  **524,489,333 字节 / 254,547 条**），多源切换、`.part` 续传、体积核对、取消、rename 全在此。
  `grep -rn "KbDownloader" test/` **零命中**（✅复算）。
- `KbPack.fromJson`（`kb_manifest.dart:88-113`）**没有 sha256 字段**；注释明写「资料只看体积」
  → 同长度损坏无法发现。
- 建议：照 `model_download_test.dart` 的样板补 6 条（成功/换源续传/Range 不支持/全失败/
  取消/体积不符），并给清单补 sha256 + 校验。

**同类**：`test/device_bridge_test.dart` 起的是**自建 mock**，`没有 import` 真实的
`device_bridge.dart` → 令牌校验、白名单求交、五个错误码**一条都没被验证过**。
白名单判断写反 = 模型可以自己放行（安全边界失效）。建议给 `DeviceBridge` 加可注入 seam
后直接起真实例测。

## 3. P1（真机上会难受 / 会造成误解）

### P1-1 等待与超时没有任何中间态（真机最难受的现场）
`acp_client.dart:254` 超时 **5 分钟**；`chat_page.dart:1301` 同轮**自动重试 2 次**
（超时不在 noRetry 名单）→ 最长静默 **10 分钟**，界面只有一个转圈。✅复算（两处都看过）。
建议：超时收到 60~90s、同轮最多重试 1 次、运行中显示「已等待 N 秒 · 取消」，
超时文案给「再发一次 / 换模型 / 看运行日志」。

### P1-2 失败页口径不统一，且启动失败是死路
`chat_page.dart:686` `_startError = '$e'` 直接把裸异常铺满整页，**没有任何按钮**；
恢复失败页（`:621`）至少还有「改为新建会话」。同类：`model_downloader.dart:164,338`
`web_search.dart:180,359` `kb_store.dart:349` 都是 `HTTP <code>` 直接上屏。
建议：统一走 `data/api_error_text.dart`；认不出也要给「看运行日志并反馈」。

### P1-3 错误翻译层本身有个文案 bug ✅复算
`data/api_error_text.dart:313`：`tr('HTTP 协议层出错：{0}.message', [error])` ——
`.message` 误写进字面量，三语表也把这个笔误一起翻译了（`en_table_data.dart:50`）。
用户会看到「…：SocketException: xxx.message」。

### P1-4 无障碍：App 覆盖了系统字号 ✅复算
`main.dart:151-154` 用 `TextScaler.linear(_appSettings.textScale)` **整体替换**
`MediaQuery.textScaler` → 用户在系统里调大字体，App 完全不跟随。改成与系统值相乘，
或加「跟随系统」档。
另：`settings_tab.dart:1038-1041` 的刷新按钮无 tooltip/Semantics；
`local_chat_page.dart:1030-1042` 待发图缩略图的关闭按钮是裸 `GestureDetector` +
12px 图标（触控目标约 18dp，远低于 48dp）。

### P1-5 i18n 漂移：切外语会看到中文（✅我自己的口径）
我的提取器：源码 **1004** 个字面量 key vs 表 **1023**；
**漏翻 49 条 / 陈旧 68 条**。（审计员另一套脚本得 45/52；差异来自多行字面量与
「非 UI 文案也被 `tr()` 包了」的判定口径 → 方案里按「约 50 / 约 70」处理。）
兜底是静默的（`dsh_i18n.dart:64` 的 `?? zh`），**不会报错**。
注意：**其中一部分陈旧条目是本次改动造成的**（删除联网搜索后，「Bing（免费・不用 Key）」
等 3 条已无主），不是老问题。
建议：加一条「源码 key ⊇/== 表 key」的门禁（`extract-keys.mjs` + 显式白名单收
`tr(变量)` 那 24 条），并补 `install/` 里的提取器对多行字面量的支持。

### P1-6 界面里的字面 Markdown ✅复算
- 更新说明页：`changelog.dart` 非注释正文 **1082 处 `**`（541 对）+ 548 处反引号**，
  50 条记录里 **45 条**中招；渲染是普通 `Text`（`release_notes_page.dart:117/127/149`）。
- i18n 表：en/ja/ko **各 15 条**含字面 Markdown。
- 源码 `tr()` 里另有 **12 处**。
- 反例（说明已有正确姿势）：模型输出走 `flutter_markdown`（`message_stream.dart`），

建议：写一个 `DshRichText`（支持 `**粗体**` 与 `` `代码` ``，约 15 行），挂到更新说明页那
3 个渲染点 → 一次清掉 1082 处；剩下 15×3 与 12 处换渲染点或直接去掉 `**`。

## 4. P2（做了更好）

- **设备通道**：`device_bridge.dart:108` 非恒定时间比较；`:105-107` 额外接受 `?token=`；
  `/open-app` 无 body 上限。建议 `constantTimeEqual` + 删 query 通道 + 限 64KB。
- **其它本地服务无鉴权**：`local_model_server.dart:416` `local_image_server.dart:186`
  都只听 127.0.0.1 但不校验 → 同机应用可白用算力（无凭据泄露）。
- **FileProvider 覆盖整个私有 `files/`**：`file_paths.xml` 有 `<files-path path="."/>`，
  `MainActivity.kt:1322-1336` 只查 `exists() && isFile`（对比 `exportTextFile` 有前缀校验）。
  当前调用点都传产物路径，暂时打不出来；建议收窄到 `attachments/ workspaces/ logs/`。
- **用不到的权限**：`ACCESS_NETWORK_STATE`（全仓无使用）、定位、相册
  （拍照/选图走 `ACTION_IMAGE_CAPTURE` / `ACTION_GET_CONTENT`）。建议删。
  另 `MANAGE_EXTERNAL_STORAGE` 会打开系统页但未声明（`settings_tab.dart:917`）。
- **`usesCleartextTraffic="true"`**：为 127.0.0.1 明文服务全局放开；建议
  `network_security_config` 只放行 127.0.0.1。
- **非原子写**：`rotation_proxy.dart:186`、`kb_store.dart:207/:237` 整文件覆盖，
  中途被杀留半份 JSON。
- **脱敏盲区**（审计员实测）：裸 hex Key、`https://user:pass@host` 不脱敏；
  真实形态都能脱敏，属潜在问题。

### 看起来可疑但实际安全的（写下来避免以后误改）
- 令牌本身：`Random.secure()` 24 字节，只经 env 传子进程，不进命令行/日志/磁盘。
- 通道路由面极小，无任意 Intent、无路径拼接、无 shell；`/open-app` 命中后仍要过用户白名单。
- 执行面全是 argv 数组，无字符串拼 shell；toolbox 6 个 .mjs 无 shell 调用。
- 导出诊断报告**确实不带 Key**（`send_log_button.dart:269-295` 只用 `containsKey`，连值都不读）。
- `ProfileInstallReceiver exported=true` 来自 androidx，有 `android.permission.DUMP` 保护 —— **别去「修」它**。
- 13 个 `SKILL.md` 无「忽略安全」类写法；`open-phone-app/SKILL.md` 明确禁止绕过白名单。

## 5. 效率与体积（P0 级发现：APK 可以砍掉一半）

release APK **237,602,532 字节（226.6 MB）**。构成（审计员 `unzip -v` 实测）：
`assets/dsh-runtime.zip` **151.8 MB（63.9%）** + jniLibs 30 个 .so **83.4 MB（35.1%）**
+ 其余 <1%。

### P0-5 运行时包里 **74%** 是 Windows / 开发文件 ✅复算
我直接读 zip 元数据复算（`@deepseek-ai/libreoffice-kit-win32-x64` 一个就 **63.6 MB**）：

```
条目 26,495   压缩后 145.0 MB
Windows 平台   829 个 · 91.1 MB（62.8%）   ← .exe/.dll/.pdb/win32-x64
开发文件    11,522 个 · 16.2 MB（11.2%）   ← .map/.d.ts/tests/docs/coverage
两类合计    12,351 个 · 107.3 MB（74.0%）
```

- 根因：`install/build-app-assets.ps1:22` 的源是**Windows 的 DSH 安装树**
  （`D:\Programs\PaopaocatDSH\app`），整目录打包；条目名还带反斜杠
  （`MainActivity.kt:1661-1663` 靠 `replace('\\','/')` 兜底）。
- 安全性：树里 `@img/sharp-wasm32` 有兜底；`node-addon-require-builtin-win32-x64-msvc`
  正是被 `MainActivity.kt:1704-1716` 用纯 JS 顶掉的那个；
  `sherpa-onnx-win-x64` / `ripgrep-win32-x64` **在树里没有 linux/android 变体**
  → 在 Android 上本来就用不到。
- **预估收益（审计员估算）**：APK **−117,747,847 B（−112.3 MiB）→ 约 114.3 MiB**；
  解包稳态磁盘 **533 MiB → 约 120 MiB**；文件数 **−55%**。
- 风险：中 —— 每次改排除规则必须真机冒烟（`dsh --version` + `make-pptx`）。
- 附带：**换更高级 deflate 收益为零**（实测 Optimal 32,920,383 vs zlib-9 32,920,395，
  差 12 字节）；只有换 solid 容器（tar+zstd 可再 −37%）才有第二段收益，
  但那要改解包器，**排在 P0 之后**。

### P0-6 两套在清单下用不到的引擎仍在包里（26.6 MiB）
`assets/models/model_manifest.json` 三个模型**全是** `engine: litert-lm`，
`changelog.dart` 也写着「llama.cpp 的 GGUF 全部下线」，但 APK 里
`libstable-diffusion.so` **39,404,168 B** 实实在在躺着。
实测闭包：SD = `libsdserver + libstable-diffusion`（16.1 MB）；
llama = 9 个 `libllama* + libggml*`（11.8 MB）→ **合计 −27,906,764 B = 26.6 MiB = APK 的 11.7%**。
硬约束：① 两套**必须一起删**（共用 `libggml-vulkan.so`）；
② **绝不能删** `libLiteRtClGlAccelerator` / `libLiteRtCompilerPlugin_Qualcomm` /
`libLiteRtDispatch_Qualcomm`（3 个共 2.0 MB，`liblitertlm_jni.so` 运行时会 dlopen 它们）。

### P0-7 知识库每问一次整份重读 34.6 MB 索引
`local_chat_page.dart:474-481` 每轮 `KbRetriever.open()` → `kb_index.dart:575`
`readAsBytes()` 把整个 `index.bin` 读进内存，**没有任何缓存**（retriever 是局部变量）。
按格式实测（32 B 头 + 每块 8+4×32=136 B）：254,547 块 → **34,618,424 B / 轮**，
外加 chunks.bin 80 次随机读。建议按 `kb.id` 缓存 + length/mtime 失效。
收益（估算）：20–70 ms/轮（UFS），多包线性放大。

### P0-8 Bloom 预筛「筛了个寂寞」：89–99% 全库通过，然后全排序
`kb_index.dart:615-623` 对全部块 `hit > 0` 即入选；`:172-175` 注释声称
「填充率约 30%、误判率约 9%」—— 那是**单比特**误判率，不是**整块**通过率。
审计员用真实中文语料等价复刻并采样 20,000 次实测：

| 查询 | 通过率 |
|---|---|
| 如何治疗感冒 | 89.0% |
| 光合作用如何进行 | 91.5% |
| 晋城是什么地方 | 93.1% |
| 第二次世界大战的起因 | 97.6% |
| 量子力学的基本原理是什么 | 98.9% |

然后 `:626-627` 对 22.6–25.2 万个 MapEntry 做**完整 sort** 只为取前 80。
建议：丢掉 Map，改 `Int32List` + 单遍有界最小堆 top-K(≈400)；
同一次访问内每块的 32 个 32 位字只读一遍。
**风险**：判定逻辑一改就要重跑 `app/test/kb_index_test.dart`（里面有「晋城」回归用例，
`:177-180` 记着当年 MinHash 翻车的历史），并显式定义 tie-break。

### 附带实测（值得记下来，避免以后按直觉改错）
- **启动路径没有重活**：随包 zip **不在启动时解包**（`unpackRuntime` 只在用户点按钮时调）。
  真正的重活在**安装期**与**首次准备运行时**：`useLegacyPackaging=true` 让系统解出
  30 个 .so / 209.76 MiB；首次准备要落 157.9 MB zip + 遍历 26,495 条目。
  解包耗时只有本机 `unzip` 实测 **4.0 s** 与代码自述「约 75 秒」，**真机未测**。
  解包峰值 683 MiB / 稳态 533 MiB（其中 70.7 MiB 是 4 KiB 块对齐浪费）。
- **建索引确实是流式**（`kb_index.dart:333` `openRead()` + `await for`，缓冲 ≤4.8 KB），
  所以「500 MB 也能建」结构上成立；但 `openWrite()` 后全是同步 `add()`、
  **无背压**，磁盘跟不上时待写数据可能堆到接近整个输出量（估算 345–426 MB）。
  建议每 256 块 `await chunkSink.flush()`。
- **外层重复压缩只换来 3.9%**：不要设 `noCompress`（会涨回 157.9 MB）。
- `dist/` 累积 **45 个 APK / 9.52 GB**（0.15→0.57）✅复算 —— 见第 6 节。

## 8. 代码与架构审计（最后一路，已回收）

### P0-9 数据丢失：配置文件非原子写，而且坏文件会被静默降级成「空配置」
- `configured_models.dart:374` 直接 `await fileOf(filesDir).writeAsString(jsonEncode(payload));`
  ✅复算 —— **没有** `.part → 校验 → rename`（同一仓库对模型/知识库下载恰恰是这么做的，说明
  团队知道这个模式）。同类直接写：`schedule_store.dart:241`、`expert_store.dart:136/181`、
  `model_store.dart:286`。
- 更危险的是**读取侧的静默降级**：`configured_models.dart:151-160` 解析失败会退化成空配置。
  于是「进程被杀留下半份 JSON」→ 下次启动读成空 → **下一次保存把这份空配置写回去** →
  用户的厂家与模型全没了，且没有任何提示。
- 建议：所有配置一律 `.part` 写 + `rename`；解析失败**不要**当成空，要报错并保留原文件。

### P0-10 原生侧只 catch Exception（18 处）→ 半截回复被当成完整回复存下来
- ✅复算：`LiteRtLmBridge.kt` **18 处 `catch (…: Exception)`**、仅 2 处 `Throwable`；
  而 `MainActivity.kt` 是 1 处 `Exception` / **34 处 `Throwable`** —— 显然只把主文件系统性改过，
  桥被漏掉了（本仓库历史上正是踩过 `UnsatisfiedLinkError` / `OutOfMemoryError` 属 `Error`
  不属 `Exception` 这个坑）。
- 后果链：native 抛 `Error` → 穿透 Exception-only 的 catch → socket 被关 → Dart 侧
  `await for` 看到流正常结束 → **半截回复被当作完整回答存进会话与落盘**
  （`local_chat.dart` 只有连接超时，没有读超时）。
- 另一处矛盾：这些 catch 走的是 `Log.w`（`LiteRtLmBridge.kt:295/528/559`）而不是 `say()`，
  **不进 App 运行日志** —— 与该文件 111-118 行自己写的设计前提
  （「`Log.i` 只进 logcat，用户在 App 里根本看不到」）直接冲突。

## 10. 第 1 批执行记录（2026-10-09 晚）

### 10.1 出包后核对脚本（P0-1）→ `install/check-release.py`

设计原则一句话：**只认包里的字节**。源码树、既有测试、任何人的判断都不算数。

三项核对：

| 项 | 查什么 | 为什么 |
|---|---|---|
| 版本同一 | 包内 `versionName`/`versionCode` == 当前 `pubspec.yaml` 推导值 | 防"改了版本号没重打包 / 发错包" |
| 落盘表自检 | `AndroidToolbox.assets` 的**每个 key** 都能在 `libapp.so` 里找到 | **0.57 就是死在这** |
| 资产同一 | `app/assets/**` 每个文件在包里逐名存在，且 **size + sha256** 相同 | 防"清单在、内容不在"和"打了旧资产" |

实现要点（都是踩出来的）：
- 包内 `AndroidManifest.xml` 是**二进制 AXML**，不是文本，grep 找不到 `versionName`。
  手写了一个刚好够用的解析器，**不依赖 aapt / Android SDK**（出包机上不一定有）。
  坑：`START_ELEMENT` 的 `headerSize = 16`（不是 8），元素体从 `off + headerSize` 起；
  按 `off + 8` 算会永远找不到 `manifest`。地面真值：解析 0.57 的真实包得到 `0.0.57` ✓。
- 顺带发现一条**既存的口径不一致**：界面 `kAppVersion = '0.57'`，而安装包
  `versionName = '0.0.57'`（来自 pubspec `0.0.57+57`）。不会让包不可用，
  但"界面显示的版本"和"系统里看到的版本"对不上 → 脚本报 WARN，不报 FAIL。

**在真实 0.57 坏包上的运行结果**（这就是它该有的样子）：

```
[PASS] 版本同一       versionName = 0.0.57（与 pubspec 一致）
[WARN] 版本口径       界面 kAppVersion = '0.57'，而安装包 versionName = '0.0.57'
[FAIL] 落盘表自检     1 个脚本在 AndroidToolbox.assets 里，但包内 libapp.so 里找不到：
                        - assets/toolbox/open-app.mjs
[PASS] 资产同一       25 个资产在包里逐名一致，size + sha256 全部相同
[PASS] 运行时包       assets/dsh-runtime.zip  150.6 MB
结论：**不要发这个包** —— 1 项 FAIL
```

配套：`install/test_check_release.py`（7 项）。它用**合成 APK** 端到端跑真脚本、
看真实退出码，两个方向都钉住：好包必须 PASS（否则每次红灯，人就开始无视它），
少一个字符串 / 少一个资产 / 版本对不上都必须 FAIL。

挂到流程里：
- `install/build-local-apk.ps1` 出包、拷进 `dist/` **之后立刻核对**，
  不过就 `throw`（可用 `-SkipVerify` 跳过，但默认是闸）；
- `install/rebuild-and-verify.ps1` 重写成：按**当前**命名找产物 → 再跑核对。

### 10.3 运行时包瘦身（P0-5）→ `install/slim-runtime-zip.py`

规则初版按"名字里有 win32/windows 就删"，于是要删

名字看着就是"纯 Windows 包"。但实际上它们被 **DSH 核心模块顶层静态 import**：

```
dsh-sandbox-local/lib/index.js    :  import { ... } from "@deepseek-ai/dsh-sandbox-windows-acl";
```

ESM 顶层 import 按规范**提升且无条件执行** → 删掉这两包，这两个核心模块一加载就崩。
而它们**合计只有 0.1 MB**。为省 0.1 MB 冒"App 起不来"的风险，纯属亏本。已加进保底清单。

同一轮还揪出/修掉了三个**规则自身**的错（全是靠"排除规则自检"发现的，不是靠眼睛）：

1. **包名被当成目录名**：`@standard-schema/spec` 的 `spec` 是**包名**，不是测试目录。
   初版按"含 spec 段就删"把它整包删了。修法：只看 `node_modules/<包名>` **之后**的段。
2. **自定义 exports 条件被当成运行时入口**：`zod` 的 `"./src/index.ts"` 挂在
   `"@zod/source"` 下、`eventsource` 挂在 `"source"` 下 —— Node 只认
   `node/import/require/default`，这些自定义条件**永不被选中**。误判会白白放弃 1.9 MB。
3. **Windows 命名的单个源文件不能删**：`default-browser/windows.js` 与
   `dsh-native-command/lib/types/file-applications-windows.js` 是被**顶层静态 import** 的
   （`import windows from './windows.js'`）。这些文件**总共 0.0 MB** ——
   省不到体积，风险却是"核心模块崩"。规则改成**只删 Windows 命名的"目录"**
   （平台包 / prebuild 变体），不删单个源文件。

### 11.1 P0-2 凭据泄漏：两条独立路径都堵了

原状（审计实测）：`parentEnvBase()` **默认全量继承 `process.env`**，
而"模式开关" `DSH_ANDROID_ENV_PASSTHROUGH` 全仓零命中 —— 机制存在但**从未启用**。

**改法（与审计建议有意不同）**：不改"让 Dart 去设那个开关"，而是把 **shim 的默认值
本身**改成安全白名单。理由：把白名单抄到 Dart 里就有**两份清单**，改一处忘一处，
要么漏凭据、要么把随包功能改坏。**清单只有一份，在 shim 里**（`DEFAULT_ENV_PASSTHROUGH`）。

默认白名单（失败安全：忘了配也不会漏）：

| 前缀 | 谁需要它 | 少了会怎样 |
|---|---|---|
| `DSH_ANDROID_` | `DSH_ANDROID_TOOLBOX` | **所有技能文件**找不到脚本 |
| `DSH_DEVICE_` | `open-app.mjs` 的地址与令牌 | 「打开本机应用」失效 |
| `AGNES_` | `make-image/video.mjs` | 免费生图/生视频失效 |
| `LOCAL_` | 本机出图端点 | 本机出图失效 |

⚠️ 审计建议的前缀表是 `AGNES_,LOCAL_,DSH_ANDROID_` —— **照抄会让「打开本机应用」失效**
（它需要 `DSH_DEVICE_TOKEN`，而 `DSH_DEVICE_` 不在那张表里）。这就是"把安全修成坏功能"。
`all` / `*` 保留全量继承（仅调试），`none` 保留不继承。

`ROTATE_API_KEY`（下面 P0-3 的令牌）**故意不在白名单里** —— 否则模型能自己
拿用户的 Key 去打代理。

**第二条路径**：老版本把含各厂家真实 Key 的配置写进
`$HOME/toolbox/rotate-config.json`（`HOME=filesDir`，模型驱动的 shell 同 uid 可读）。
现在配置走 **stdin 管道**（`--config-stdin`），令牌也一起走管道
（不进 argv —— `/proc/<pid>/cmdline` 同 uid 可读）。磁盘上只留
`rotate-state.json`，内容**只有 `{"lastGood":{...}}`**，没有任何凭据。

⚠️ **升级清理**：新版本不写那个文件了，但**已经装过老版本的手机还留着它** ——
所以在 `ensureRunning` 里顺手 `delete`。不删就是"新洞堵了、旧洞还开着"。

### 11.2 P0-3 轮换代理加客户端鉴权（+ 端口不再固定）

原状：监听 `127.0.0.1:39321~39330`，**全文没有任何 401/403 分支**。
而 loopback 在整机上是共享的 —— 同机任何带 INTERNET 的应用扫这 10 个端口
就能 `POST /v1/chat/completions`，**用用户的 Key 花钱**。

改法（照抄设备通道那套）：
- **随机令牌**：`DshRuntime.rotateToken` 惰性生成、进程内稳定（32 位十六进制，
  `Random.secure()`）。为什么惰性 + 静态：Dart 侧有两处要读它（下发代理 / 写进
  DSH 环境），而生成时机不能依赖启动顺序 —— 谁先读都拿到同一个值。
  overlay 用 `apiKeyEnv: ROTATE_API_KEY` 引用它，于是 DSH 会把它当 provider 的 Key
  发成 `Authorization: Bearer <token>`。
- **等时比对**：两边各算 sha256、再比定长摘要（`timingSafeEqual`）。不用 `===`
  是因为那样耗时随"猜对几个字节"变化，可被逐字节爆破；先比摘要也顺手解决了
  `timingSafeEqual` 对不等长输入会抛的问题。
- 也接受 `x-api-key: <token>`（万一 DSH 用那个头）。
- **`/health` 也要令牌**：否则它就是一个"免费探测这个端口是不是轮换代理"的信号。
- **端口改用 `--port 0`**（系统挑空闲端口），真实端口从就绪行读回来再写进 overlay。
  固定 10 个端口本身就是"可被扫到"的放大器。同时删掉了原来"10 个端口逐个试"的循环。
- **没令牌又没 `--no-auth` → 拒绝启动（退出码 3）**。失败安全：一旦 Dart 侧忘了传，
  不能**静默**回到"谁都能用"。`--no-auth` 只留给本地调试/单测。

**顺手修掉一个既存缺陷**：旧代码在"代理已在跑"时只**重写配置文件**、不重启，
而代理只在启动时读一次配置 —— 也就是说"改了池子成员但没生效"。
现在比配置哈希，变了就重启。

### 11.3 P1-1 等待/超时：我没有照抄审计的建议，理由如下

**原状**：`request()` 的默认超时是 **总时长** 5 分钟（从发出算到整轮结束），
而超时**不在** `noRetry` 名单里 → 自动重试一次 → 最长静默 **10 分钟**，只有一个转圈。

**审计建议**是"超时收到 60~90s、同轮最多重试 1 次"。**我没有照做**，因为
"总时长砍到 90 秒"会**砍掉正常回合**：多轮工具调用、或端侧小模型对长上下文做
prefill（这段时间一个 token 都不吐）都能轻松超过 90 秒。

**改法**（治"静默"而不是治"慢"）：
- **空闲超时**：新增 `request(idleTimeout:)`。判据是"连续 N 秒**一行输出都没有**"，
  而不是总时长。`_lastLineAt` 在 `_onLine` 里更新（**任何一行**都算，
  包括解析失败的行 —— 我们只关心"子进程还活着")。
  `promptIdleTimeout = 180s`（保守：端侧 prefill 可能一分多钟不吐字），
  `promptHardTimeout = 30min`（兜底，防止真的无限挂着）。
  ⚠️ 180 秒这个数**需要真机实测后调**，它不是从设备上量出来的。
- **超时不自动重试**：`e is TimeoutException` 进 `noRetry`。重试 = 让用户再干等一遍，
  静默时间直接翻倍（旧代码就是这样拿到 10 分钟的）。
- **可见进度**：消息流里那行 `正在处理…` 后面加「已等待 M:SS」，**每秒自己走**。
  为什么要独立小部件：放在页面里 `setState` 会一秒重建整个消息列表（真机掉帧）。
  为什么放在**消息流**而不是顶栏：顶栏很挤（三个按钮在 320dp 上已接近溢出，
  `chat_top_bar_test.dart` 盯着这条），消息流全宽且正是用户盯着看的地方。
  为什么给"时间"而不是"进度条"：我们**拿不到**真实进度（ACP 只告诉"有输出/没输出"），
  假装知道比不给更糟。时间是真的。
- 开始时刻放在 `LiveSession.turnStartedAt` 上，切页回来**接着显示**而不是归零
  （"我到底等了多久"正是这条要解决的问题）。
- "取消"其实一直有（顶栏「停止」+ 输入框停止键），审计那条说得不完全准。

### 12.4 P0-7 索引缓存（提交 `7426fdc`）
**问题**：`KbRetriever.open()` 每次调用都把整份 `index.bin` 读进内存，而本地对话
**每一轮**都调它（`local_chat_page` 的检索段）。实测那包 `34,618,424` 字节
（32B 头 + 254,547 块 × 136B）—— 每问一句白读 35 MB。
**改法**：按路径缓存，`(size, mtime)` 一起判失效（mtime 秒级粒度、size 可能恰巧相同，
单独用哪个都不稳）；**48 MB LRU 预算**（单个超预算也留，否则那包永远查不了）；
重建索引后显式 `clearCache()`。
**实测**（合成同规模索引，本机 NVMe）：`open` **36 ms** → 缓存命中 **345 µs**，
`identical()` 为真 → 约 **105 倍**。
**测试**：`kb_index_test` 缓存 5 项（同实例、重建失效并查到新内容、clearCache、
内存记账不重复累加、无索引时不污染缓存）。

### 12.5 P0-8 预筛：Map + 全排序 → 单遍扫 + 有界堆（提交 `7426fdc`）
**问题**：`hit > 0` 通过率实测 **89–99%** → 旧实现每轮把 22.6~25.2 万条装进
`Map<int,int>`（装箱）、`entries.toList()` 复制一份、再**全排序**只为取前 80。
**改法**：容量 `candidates` 的**有界最小堆**（O(n log k)、内存常数）。
`candidates` 80 → **400**（位命中数区分度差，只取 80 会让它决定谁能进精排；
400 只是把精排输入放宽几十 KB，最终仍由真实词重叠决定）。
**A/B 实测**（254,547 块、通过率 100% 最坏情况）：**64 ms → 18 ms**（3.6 倍）。
⚠️ A/B 中两条路选出的候选集合**不一致** —— 恰好印证了"tie-break 未定义"：
通过率 100% 时全体命中数相等（25 万路并列），而 Dart `List.sort` **不保证稳定**，
旧代码选谁其实是未定义的。现在 tie-break 显式化（hit 相同取 chunkId 小），
精排的分数并列也补了显式 tie-break，并加了 3 项确定性测试。
**测试**：`kb_index_test` 13 → **21 项**，"晋城"那条老回归用例仍通过。
**踩坑**：第一版并列测试用"12 条相同短条目"构造 → 只出 1 条命中。
真因是 `KbIndexer` **不按条目切块**：它攒到 ≥2400 字符再按 600 字切，
短条目被并成一块。改成"一条长文本、晋城反复出现"。

### 14.1 FileProvider：从"整个私有目录"收成白名单
原来是 `<files-path path="." />`。现在按**真实代码路径**逐条核对后收成 4 条：

### 14.2 明文流量：裸布尔值 → 写明理由的策略文件
`android:usesCleartextTraffic="true"` → `res/xml/network_security_config.xml`。
**这一份不是收紧，行为与改动前一致** —— 把话说清楚，不假装加固了：
本 App 明确支持"明文 ws 连局域网桥"（`start-bridge-ws.cmd`，文档写着"明文，仅私有网络"），

### 14.4 脱敏补一个真缺口

## §17 随包 ffmpeg（口播/短剧的底层）—— 构建与验证记录

**日期**：2026-10-11　**触发**：用户「先把 ffmpeg 打进去（口播/短剧）」

### 17.1 做了什么

自编 Android arm64 的 `ffmpeg` / `ffprobe`（静态链接 libav* + **libx264** + aac），
以 `libffmpeg.so` / `libffprobe.so` 的形式放进 `jniLibs/<abi>/`。
脚本 `install/build-ffmpeg-android.sh`（已入库，可复现：官方源码 + 本机 NDK 28.2 + API 24）。

**为什么必须是 `lib*.so`**：Android 不允许从 App 数据目录执行文件（实测 EACCES，
见 `android-exec-shim.cjs` 顶部注释）；只有 Gradle 打进 `lib/<abi>/` 并解压到
`nativeLibraryDir` 的文件才允许执行。

### 17.2 实测事实（可复现的命令与结果）

| 检查 | 命令 | 结果 |
|---|---|---|
| 架构 | `file ffmpeg` | `ELF 64-bit LSB pie executable, ARM aarch64, stripped`，interpreter `/system/bin/linker64` |
| libx264 编入 | `grep "CONFIG_LIBX264 1" config.h` | 命中 |
| 依赖面 | `readelf -d ffmpeg` | 只有 Android 公开 NDK 库：`libm/libandroid/libcamera2ndk/libmediandk/libz/libdl/libc` |
| 体积 | `stat` + `gzip -9` | **静态双份**：+42.8 MB（安装）/ +20.6 MB（APK，100.7 → 121.3 MB）<br>**共享库（最终采用）**：**+23.8 MB**（安装）/ **+10.9 MB**（APK，100.7 → 约 **111.6 MB**） |
| 依赖闭合（共享库版） | 逐个 `readelf -d` | 跨库依赖全在随包的 8 个 `.so` 内；外部只有 Android 系统/公开 NDK 库 ✅ |

### 17.3 功能验证（本机没有模拟器/真机，用 qemu 真跑）

动态版依赖 Android 的 `/system/bin/linker64`，**qemu 跑不了**；所以另编了一个
**完全静态**的同源版本（`--disable-jni --disable-mediacodec`，其余 flag 相同）用于验证。
用 `qemu-aarch64-static` 真跑三种实际场景，再用**电脑上独立的 ffprobe** 校验产物：

| 场景（对应真实流程） | 结果 |
|---|---|
| ① `libx264` + `aac` 编码 → mp4 | ✅ 校验出 `h264,video,320,240` + `aac,audio,44100` |
| ② **一张图 + 一段音频 → mp4**（口播的典型形状） | ✅ `h264` + `aac`，容器 `mov,mp4,m4a,3gp,3g2,mj2`，时长 1.000s |
| ③ `-vf scale`（短剧拼接/缩放的形状） | ✅ `h264,160x120` |

**结论与边界**：**编解码管线本身已被证明可用**（同一个源码、同一份 x264、同一套 configure，
只差 libc 链接方式与硬件解码开关）。
但"**在真机上能被执行**"仍**未测量** —— 那只能靠装机验证（这也是把它做成
`lib*.so` + shell 函数 + `AGNES_FFMPEG` 三条路都通的原因）。

### 17.4 遗留（用户已知情）

* ✅ **已做**（用户 2026-10-11 选「3 和 1」的「3」）：改成**共享库**后
  安装体积 42.8 → **23.8 MB**、APK 121.3 → **约 111.6 MB**。
  实现要点：`--enable-shared` + `patchelf --set-soname`（版本化名字进不了 jniLibs，
  且 APK 不支持软链）+ **用 `readelf` 的 NEEDED 驱动打包**（只带真正需要的库，
  依赖闭合自检写进构建脚本）。8 个 `.so` 也已纳入出包闸门的"必须存在 + AArch64"检查。
* **字幕方案（重要设计决定）**：这个 ffmpeg **没有** `subtitles`/`drawtext`/`ass`
  滤镜（NDK 里没有 libass/freetype）。所以字幕走**App 侧用 Flutter 绘制**，
  ffmpeg 只做「图+音频→mp4、拼接」——这也正好是 §17.3 已用 qemu 验证过的那几件事。
* **GPL 合规**：libx264 是 GPL → 这个 ffmpeg 是 GPLv2+。「设置 → 关于」新增
  「第三方组件与许可」（许可全文 + 相应源码地址），仓库 `docs/第三方许可.md` 同步。
