## 1. 切换模型不再重建会话（用户第 1 条）

> 「切换模型不要重建会话，看看有没有这个问题发生」

**老口径**：`_applyModelChangeOnce` 里 `configChanged = st.sig != _spawnedConfigKey`，
`st.sig` 是**整份配置**（所有厂家 / 所有模型 / 所有组 / 所有 Key）的指纹。
于是"用户改了**别的厂家**的 Key、或往清单里勾了一个新模型"也会让它判成"配置变了"
→ 走 `_restartSession()` 重启进程。真机日志里"提示说没重建、实际换了会话"
（`docs/CHANGES-2026-10-14.md` §3）就发生在这一条路径上。

**新口径**：判据换成「**当前选中这条路由自己的管路**」——

```
provider 定义（api / baseUrl / apiKeyEnv）
+ 那个 provider 的 Key **当前值**（Key 变了必须重建，否则进程还揣着旧 Key）
+ 那个 provider 下的模型条目（给这个厂家加了模型 = 进程里没注册过）
+ 轮换组成员清单（组里转发目标换了）
```

没变 → 直接会话内切（`session/set_config_option`），**一个进程都不重启**。

**改在哪**
* 新增 `app/lib/state/spawn_signature.dart`：`providerPlumbing()` / `selectedRoutePlumbing()` /
  `providerOfRoute()`。抽成纯函数就是为了能直接测（界面层要真起 node 进程）。
* `app/lib/ui/pages/chat_page.dart`：`_routePlumbing()`（spawn 前取）、字段
  `_spawnedRoutePlumbing`、`_applyModelChangeOnce()` 用 `routeChanged` 代替 `configChanged`；
  成功文案改成「已切换到 X（会话没重建，上下文还在）」。
* `app/lib/state/session_registry.dart`：`LiveSession.spawnRoutePlumbing` —— 切页回来/页面重建
  要读回它，否则只能退回老口径。

**兼容与兜底**：没记过管路的第一次（老代码升上来）仍按整份指纹保守判一次；
`_switchModelInPlace()` 返回 false（老运行时 / 没注册过）时照旧重建，
而现在重建会 `session/resume` 同一个会话（0.75 那轮的 B 修复）。

**验证**：`app/test/spawn_signature_test.dart`（8 条）——"改别的厂家的 Key → 管路不变"、
"改自己的 Key/baseUrl/模型条目 → 管路变"、"轮换组成员变了 → 变"、
"同一条路由两次取值稳定（否则每次切模型都重建）"。

## 2. 会话列表显示时间 + token 用量（用户第 2 条）

> 「我记得以前提过要求会话都是可以显示时间和用了多少tok」

* **时间**：一直就有（`ACP session/list` 的 `createdAt`）；这次把**本次运行的会话**也补上了

  `data/display_format.dart` 的 `formatTokens()`（**1024 进制**，与「应用信息」里的
  体积口径同一套算法）。
* **取不到就不显示那一段**（`tokensLabel` 返回空串）—— 绝不画一个编出来的 `0 tok`。

**验证**：`app/test/display_format_test.dart`（口径 + 负数）、
`app/test/session_shell_filter_test.dart`（`readSessionFacts` 的空壳判据仍然成立）。

## 5. 音乐播放器 + 后台播放：我的结论是**不做**（用户第 5 条）

> 「有没有必要加个音乐播放器，后台播放音乐（这个你思考）」

**结论：这一版不做。** 四条理由，按重要性排：

1. **后台播放要动原生最重的那一块**：Android 上"切到后台继续放 + 通知栏/锁屏控制"
   需要**前台服务** + `MediaSession`。项目里确实有一个前台服务（`DshSchedulerService`，
   给定时任务保活用），但它的语义是"有任务在等"，拿来播音乐会显示一条
   "DSH 正在后台运行任务"的通知 —— 用户看到的是**错的通知**。
2. **与本项目的既定方向相反**：刚做完包瘦身（106.3 → 76.3 MiB），并且一直坚持"权限最少"。
   音乐播放要吃 `READ_MEDIA_AUDIO`（或 SAF）+ `FOREGROUND_SERVICE_MEDIA_PLAYBACK`，
   还要在"应用信息 → 权限"里多出一条让用户疑惑的东西。
3. **现有能力已经覆盖大半**：工作区/资料库里点音频文件**能在 App 内播放**
   （`media_preview_server.dart` + WebView，0.71 那轮做的）。缺的只是"切到后台继续放"。
4. **我无法在本机验证后台音频**：这个环境没有真机/模拟器，音频被系统挂起/杀进程的
   行为因 ROM 而异。**没验证过的原生功能不该进包** —— 这是我这几轮一直守的线。

**如果以后要做，最小可交付是这样**（先记下来，等你点头）：
① 先做一个**纯 App 内**的播放列表（复用 `media_preview_server` + WebView，零新权限）；
② 再加一个新的前台服务（**不复用**定时任务那个），通知文案是"正在播放：<文件名>"；
③ 最后才考虑 `MediaSession`（锁屏/耳机键控制）；每一步都要真机验证过再往下走。

## 6. 像素主题：从"换色 + 直角"改成"换一整套视觉"（用户第 6 条）

> 「像素主题变化不大或者说根本没有变化，我要的是大变样子，
> 界面字体风格和其他两个完全不一样的」

**之前**：像素皮肤只改了色值 + `radiusScale = 0`（方角）。用户说得对 —— 那确实"变化不大"。

**现在**（新增总闸 `DshPalette.pixelStyle` → `DshMetrics.pixelStyle`，**别在别处判皮肤 id**）：

| 维度 | 普通皮肤 | 像素皮肤 |
|---|---|---|
| 字体 | 系统默认 | **设备自带等宽字体**（`fontFamily: 'monospace'`）+ 字距 0.4 |
| 描边 | 1 dp 细边 | **2 dp 硬边**（`DshMetrics.borderWidth`，走 `DshColors.panel()` 与主题里的各处 shape） |
| 面板底 | 半透明玻璃（`surfaceHigh`） | **不透明实心板**（`surfaceStrong`，"实心板子"而不是磨砂玻璃） |
| 投影 | 柔和光晕（blur 44） | **无模糊硬方块位移**（blur 0 · offset 4,4 + 左上 1px 高光） |
| 底纹 | 干净近黑底 + 顶部柔光 | **+ 扫描线**（3 dp 一条 · 5% 透明，`dsh_grid.dart`） |
| 水波纹 | Material 水波 | **关掉**（`NoSplash`，方块 UI 上的圆形扩散很出戏） |

⚠️ 两处**刻意不做**，理由写在代码注释里：
* **不随包带像素字体**：中文像素字体 5–10 MB，刚瘦下来的包不能为皮肤加回去；
  现成像素字体多数只覆盖拉丁字母，中文会掉回系统字体、变成"中英两套风格"。
  等宽字体是"设备自带 + 覆盖中文 + 同气质"的最小代价方案。
* **扫描线只给像素皮肤**：普通皮肤保持"干净的近黑底 + 柔光"（用户当年明确否掉了网格线，
  见 `dsh_grid.dart` 顶部）。

**验证**：`contrast_test`（遍历 `DshPalettes.all` 查 WCAG AA，像素皮肤的正文/次要/强调色
在 `bg`/`bgSoft` 上仍 ≥ 4.5）；`theme_skin_test` 补了像素皮肤这几条特征断言。

## 8. 公众号二维码长按 → 唤起微信扫一扫（用户第 8 条）

> 「关于的那个公众号二维码可不可以长按弹出扫描激活微信进入公众号」

* 原生新增 `openWechatScan`（`MainActivity.kt`）：`weixin://dl/scan` + `FLAG_ACTIVITY_NEW_TASK`，
  返回 **`ok` / `no_wechat` / `failed:<msg>`**。
* Dart：`DshHost.openWechatScan()`（`local/dsh_runtime.dart`）。
* 界面：`settings_tab.dart` 的「关于」——二维码整块可**长按**，下面加一行明示文案
  「长按上面的二维码 → 直接唤起微信扫一扫」（手势是隐式的，不写没人知道）。
* **三种结果都如实说**：成功 → "已打开微信扫一扫 —— 对着上面这张二维码扫一下就行"；
  没装微信 → "这台机器上没找到微信，可以自己打开微信扫一扫"；被拦 → 失败原因。
  **绝不说"已进入公众号"** —— App 只能把微信叫起来，进不进得去由微信决定。
* 为什么不是 App 自己扫码：那要加相机权限 + CameraX + 识别库（几 MB + 一套权限），
  而微信本来就自带扫一扫。App 的职责只是**把它叫起来**。

**待真机验证**：① 装了微信的机器长按 → 微信扫一扫被拉起；② 没装微信 → 提示文案正确。

## 10. 这一轮**自己的测试抓到的问题**（都是真 bug，值得记）

1. **轮换组的管路永远读不到**：`rotate` 是个**虚拟厂家** —— 它不出现在
   `cfg.providers` 里，而函数开头是"查不到这个 provider 就返回空串"，
   于是整组信息被吞掉。后果：**改了组里的成员清单却不重建进程**，新成员根本没
   在进程里注册过（切过去只能失败）。修法：`rotate` 分支**上移**到 provider 查找之前，
   并把每个成员各自的管路也串进来。
   （这条是 `spawn_signature_test` 的"③ 轮换组"当场抓到的 —— 写测试的价值就在这。）
2. **像素皮肤的字体其实没生效**：`ThemeData(fontFamily:)` 只影响"由主题推导"的样式，
   而 `copyWith(textTheme: …)` 与 `appBarTheme.titleTextStyle` 是**我们自己写死的**，
   不带 `fontFamily` 就把全局字体族**盖掉了** → 像素皮肤只变色、字体没变。
   这正是用户抱怨的"变化不大"的成因之一。修法：加一个 `skinFont()` 包装，
   把我们声明的每个文字样式都过一遍。自测（`theme_skin_test`）当场抓到。
3. **i18n 扫描器的 24 字符窗口**（跨轮踩到两次，写进笔记）：它只看 `tr(` 后面
   **紧跟**的那 24 个字符里有没有 `tr(`。两种写法会**安静地漏掉**翻译：
   ① `context.tr(` 换行再写字面量；② 把中文放进 List 再 `tr(list[i])`。
   两种都表现为"表里没有、切外语显示中文、不报错"。这轮的猫咪 6 句就是第 ② 种，
   改成 `switch` + 每句 `tr('字面量')` 才进表。

## 13. 会话里的**联网搜索**：AnySearch（用户 2026-10-15 选定「B 方案」）

### 13.1 为什么走 MCP 的 http transport（而不是塞脚本 or 改运行时）

**读了运行时的源码才定的**（不是猜）：`node_modules/@deepseek-ai/dsh-acp/lib/index.js`
的 `resolveMcpConfigs()` 支持两种 transport，而且约束写得很死：

* **stdout**：`{name, command, args, env}`，其中 **`command` 必须是绝对路径**
  （`isAbsolute()` 早退）—— 手机上还得让那个文件**可执行**；
* **http**：`{name, type:'http', url, headers}` → 转成 `streamable-http`
  （`headers` 是**有序 name/value 条目**，不是普通 map，重复键会被拒）。

AnySearch 官方**自带** Streamable HTTP 的 MCP 端点 `https://api.anysearch.com/mcp`
（README 里给 Claude Code / OpenCode 的配置都是它），所以走 http：
**不起子进程 ⇒ 完全绕开 Android「App 私有目录不能执行文件」那一串坑**
（bash/node 那套 exec shim 就是为它而生）。改动面因此只有一个字段。

## 15. 真机实测反馈（用户当天就报了）：**完整包里的运行环境没被用上**

> 用户原话：「paopaocat-preview-0.75-20261015-full-arm64-v8a.apk 首次安装说是有 32 mb
> 运行环境不随包」+ 一张真机截图：卡在「首次使用：准备运行环境」，
> 文案写着"不再放进安装包里"，错误是
> `准备失败：下载运行环境时出错：TimeoutException after 0:00:20.000000`。

### 15.1 根因（打包时就怀疑、用户一测就坐实）

0.75 为了让 APK 瘦 30 MB，把**从 APK asset 里取 `dsh-runtime.zip` 那条路整个删了**
（`MainActivity.kt` 里只剩一句注释），改成"启动时按 `runtime.json` 下载 + 校验"。
于是：

| 现象 | 原因 |
|---|---|
| **完整包也被要求下 32 MB** | `build.gradle.kts` 的 `DSH_ANDROID_INCLUDE_RUNTIME=1` 确实把 zip 打进 `assets/` 了，但**没有任何代码去读它**（Kotlin 的 asset 通路删了，Dart 的 `ensureRuntimeZip()` 只认清单+下载） |
| **首次安装直接失败** | `ensureRuntimeZip()` 先去拉 `runtime.json`（raw → jsDelivr，每个源 20 s 超时）。用户那个网络两个源都超时 → 连"本地已有 zip 就放行"的兜底都到不了（本地本来就没有） |

也就是说：**完整包的卖点（装完即用、没网也能打开）当时是假的**，而且比精简包更糟 ——
精简包至少文案是诚实的（"不在安装包里"）。

### 15.2 改了什么

**原生（`MainActivity.kt`）** —— 恢复 asset 通路，但**两种包都要能用**：

* 加回 `RUNTIME_ASSET = "dsh-runtime.zip"`（常量注释写清"完整包有、精简包没有"）；
* 新增 `hasRuntimeAsset()`（`assets.open` 试开）与 `copyRuntimeAssetTo(dest)`（流式拷到临时文件再改名）；
* `unpack()`：缺 zip 时**先试 asset**，没有再抛原来那句能读懂的话；
* 新频道方法 `hasRuntimeAsset` / `copyRuntimeAsset`（给 Dart 用；`copyRuntimeAsset` 返回字节数，没 asset 返回 0 而不抛）。

**Dart（`local/runtime_bootstrap.dart`）** —— **随包自带优先**：

* `ensureRuntimeZip()` 最前面加 ⓪：本地还没有 zip 且 `hasRuntimeAsset()` → 取出来；
* **取出来之后就跳过清单**（⓪'）：完整包不再为"校验"去联网等 20 秒（源连不上就是 40 秒），
  这正是把用户那次超时堵住的地方；运行时要真更新，走 native `RUNTIME_VERSION` 那条重解压通路；
* `RuntimeBootstrapResult` 多一个 `fromAsset`，让界面能说清"这是取出来的、不是下载的"；
* 新增两个**只给测试**的注入口（`hasAssetOverride` / `copyAssetOverride`），
  这样"随包/不随包"两条路都能在单测里跑，不需要真机。

**界面（`ui/setup_page.dart`）** —— 文案分成两套（真机反馈的直接来源）：

* 自带：`运行环境**随这个安装包自带**（约 32 MB）—— **不需要联网**，直接在本机解开…`，
  进度里说"正在从安装包里取出运行环境…"；
* 不带：保留原来那段诚实的说明（"不在这个安装包里……第一次打开时下这一次"）。

### 15.3 验证

* `flutter analyze` 零问题；全量 **1005 通过 / 3 跳过 / 0 失败**；i18n **1715 / 1715 · 0 漂移**。
* `test/runtime_bootstrap_test.dart` 新增两条（把真机那次故障钉住）：
  ① **自带 + 更新源连不上 → 仍然 ok、`fromAsset=true`、`downloaded=false`**（模拟 `127.0.0.1:1`）；
  ② **不带 → 行为不变**（没 asset 就不去取、连不上就如实失败）。
* 重新出包并复验（完整包/精简包，见 §16）。

### 15.4 追加：`RUNTIME_VERSION` 1 → 2（用户追问"完整版不是一直能覆盖安装吗"）

用户那句追问点到了要害：**覆盖安装一直是可以的**（同签名、同 versionCode），
我上一条把"看不到新第一屏"说成了"要先卸载再装"，那是不准确的说法。真正的事是：

* `isRuntimeReady()` 看的是 `.dsh-runtime-<RUNTIME_VERSION>` 这个标记文件 ——
  **内容版本不变时，覆盖安装不会重新解压**，所以完整包里的新运行环境"装了也用不上"；
* 而这次运行环境**真的变了**（多了 AnySearch 搜索后端插件），按规矩就该 +1。

所以把 `RUNTIME_VERSION` 从 `"1"` 改成 `"2"`，并在常量注释里写死这条规矩
（**运行环境内容一变就必须 +1**，否则覆盖安装拿不到新那份）。改完之后：

| 包 | 覆盖安装后的行为 |
|---|---|
| **完整包** | 标记变成了 `.dsh-runtime-2`，判定"没就绪" → 进准备页 → **直接从安装包里取**（§15.2 的改动）→ **不联网**、不下载 → 解压出带 AnySearch 的新运行环境 |
| **精简包** | 同样重新解压，但用的是本地那份 `runtime.zip`；它与 `runtime.json` 的 sha256 一致 → **也不下载**（内容还是旧的，想拿新的要走发版后的 `runtime.json` v2） |

这也顺带把"完整包"的定位说清了：**它是给全新安装（以及需要随包更新运行环境时）用的**，
覆盖安装一直都能装，只是"要不要重解压"由 `RUNTIME_VERSION` 决定。

⚠️ **仍未验证**：真机上这两件事 —— ① 完整包覆盖安装/首次安装都不再要求下载；
② 重新解压后会话里的搜索是否真的走 AnySearch 原生后端。下次装机时看两处即可确认：
准备页文案（"随装包自带、不需要联网"）与搜索结果的来源。

### 9.1 换厂家之后「只剩一段摘要」（用户第 1 条）

**现象**：同厂家切模型没事；换厂家后感觉"只保留了摘要"；多次进出对话"感觉还是丢了"。

**根因（两层，缺一不可）**：
1. **换厂家必然重启进程** —— 每个厂家的 Key / 端点是 **spawn 时**注入的环境变量（`_spawnState` → `AcpClient.start(apiKeys:)`），不重启拿不到新 Key。于是走 `_restartSession()`，而它第一件事是 `_messages.clear()`。
2. **恢复回来的历史没进消息流** —— `session/resume` 按协议只回 `{configOptions}`、不带历史，App 自己读会话文件回放；但那批消息被画进一个**独立的「历史记录 · 只读回放」折叠框**（`if (_resumed) _historyBlock()`），**不并进 `_messages`**，且只取正文（reasoning / 工具调用全丢）、只留 40 条。用户看到的"摘要"就是那个框。

**模型其实没忘**：`dsh-agent-loop` 的 `resumeWith()` 是 `persistence.open()` → `handle.read(0, undefined)` → **整段事件作为 seed** 重建会话，上下文完整。日志佐证：16:28:26 那轮（重启后）思考时仍引用了更早那句「现在都不能用吗」。

**修法**：新增 `_mergedMessages`（磁盘历史 + 本次运行消息，按「角色 + 正文」去重）；`_historyBlock()` 降级成一条状态说明条。另外读会话记录时**过滤 `<system-reminder>`** —— DSH 会把工作区说明作为**独立的 `user/message`** 落盘，既不该回放，也会让去重键对不上而重复显示。

### 9.2 几个会话来回切之后，点别的功能窜出会话页（第 2 条）

**根因**：工作区页里点一条会话 = `Navigator.pop()`（关工作区页）**紧接着 `_openChat()` 又 push 一个会话页**，而**底下那个旧会话页从来没被关掉** → 会话页一层层叠；在最上面那层点底部导航只弹掉一层，**露出来的是下面那个会话页**（日志 16:40:26/27/28 连着三次「返回：关掉当前页」）。

**修法**：用 `_chatRoute` 记住当前会话页，`_openChat()` 入口先 `Navigator.removeRoute(stale)` —— 保证栈上**最多一个会话页**（`removeRoute` 不播返回动画，也不把"用户按了返回"的语义混进上一次的返回值）。

### 9.3 面板太透明：输入时字和底版糊在一起（第 3 条）

**根因**：深色皮肤 `surface` 只有 **7% 白**（`0x12FFFFFF`）—— 那是玻璃卡片的设计语言，但输入框要**压一段正在键入的文字**，7% 白等于没底。`inputDecorationTheme.fillColor` 与 `input_bar.dart` 用的都是它。

**修法**：新增 `DshPalette.fieldFill`（**不透明**：浅色 `#FFFFFF` / 深色 `#1B2126` / 像素 `#1C2032`），输入框统一改用它；**不动 `surface`**（`theme_skin_test` 钉住"深色 surface alpha < 0.2"，且全 App 卡片都吃它 —— 改一处会把所有玻璃卡变成实心板）。

⚠️ 深色那个值不是随手挑的：`contrast_test` 要求 **textFaint（占位字）在 fieldFill 上也过 AA 4.5**。只要 fieldFill 明显比 bg 亮，textFaint 就掉到 **4.44** → 所以取"比 bg 略亮一点点"的 `#1B2126`（正文约 13:1、textFaint 约 4.71），框的位置靠**描边**交代。

### 9.4 二维码长按 → 微信「对不起，当前页面无法访问」（第 6 条）

**根因**：`weixin://dl/scan` 是微信的**内部** scheme，微信已拒绝外部调用、自己画一张错误页；而原生只做 `Intent(ACTION_VIEW)` + `startActivity`，**只要 Intent 被任何应用接住就返回 ok** → 变成"说谎的成功"（App 弹「已打开微信扫一扫」，屏幕上却是微信画的错误页）。社区实证同现象：「`weixin://dl/...` 打开都显示 对不起，当前页面无法访问」「以前可以，现在不行了」。

**修法**：① 原生先 `resolveActivity` 且**只认 `com.tencent.mm`**（Manifest 补 `<package android:name="com.tencent.mm"/>` 应对 Android 11+ 包可见性）；② 新增 `saveImageToGallery`（MediaStore，API 29+ 免权限；<29 如实说"这台 Android 版本需要存储权限，已跳过"，**不申请权限**）；③ 长按改弹三条真走得通的路：复制公众号 ID / 存到相册（微信 扫一扫 → 右上角相册）/ 仍然试一次唤起。**任何分支都不再说"已打开微信扫一扫"。**

### 9.5 设置页归纳 + 彩蛋（第 3 / 8 条）

### 9.10 这一轮踩到的两个"测试写作"坑（防复发）
