## 一、回答被长度上限截断，界面却说不出话

### 1.1 证据就在你自己的报告里

你的真机报告有一轮：

```
01:23:18.066|生成完成：首字 2617ms · 768 段 · 26.7 段/s（复用=false）
```

**768 正好等于 `groundedMaxTokens`** —— 那一轮不是答完了，是被 `max_tokens` 砍掉的。

### 1.2 为什么界面一个字都不说

`localChatStream` 原来**只检查一件事**：「这个流有没有正常收尾」
（没有就报"半截回答"）。它**不检查 `finish_reason == 'length'`**。

而 `length` 是**成功**的一轮 —— 只是没写完。于是：

* 半截回答被当成完整回答存进会话、落盘；
* 界面上没有任何提示；
* 用户看到的只是"句子说到一半没了"——**跟"答得乱七八糟"长得一模一样**。

### 1.3 修法

| 层 | 改动 |
|---|---|
| 消息模型 | `LocalChatMessage.truncated` 标记（与已有的 `kbHits` / `usedWeb` 同一路子，会落盘、刷新后还在） |
| 流函数 | 新增**出参** `notices`；看到 `finish_reason == 'length'` 就塞一个 `'length'` 进去 |
| 界面 | 气泡下方明确写「这条回答顶到了长度上限、被截断了（**不是答完**）。可以再发一句「继续」，或者把问题拆小一点再问。」 |

**为什么用出参而不是抛异常**：抛异常会把已经吐出来的正文丢掉；
而静默当成完整回答，就是上面那条。所以**既不能丢，也不能不说**。

## 二、旧切法索引：对话页现在会说，而且给"怎么办"

### 2.1 这条比看上去严重

知识库页从 0.65 起就会把旧索引标成「这是**旧切法**建的，检索会不准」。
但用户碰得最多的是**「本地对话」页** —— 那里原来一个字都不说。

更要紧的是第二层：

> **旧切法的索引会把 0.66 新加的相关度门槛废掉。**

旧切法把好几篇互不相关的文章揉进同一块（实测 12 篇 → 2 块，一块里 9 篇），
那个块跟**任何**问句都能对上 ≥2 个词 —— 正好过门槛。

这**不能怪门槛**（它没权力判断一块里混了几篇），是索引本身没重建。
所以结论很难听但必须说清：

> **索引没重建的用户，0.66 那次修复对他几乎无效，而他根本不知道。**

### 2.2 修法

* 判定抽成可测的纯函数 `legacyChunkPackNames()`（放 `kb_index.dart`）——
  "该提示却没提示"是个真缺陷，不能只靠界面上肉眼看；
* 对话页据此渲染提示，并给一个**「去知识库页重建」**按钮（从知识库页回来会自动重查，
  重建完提示自己就消失了）；
* 提示里写清"在本机重建，不联网、不花额度"。

### 2.3 顺带的好处

0.66 的 `[dsh-kb]` 日志已经会打印 `切法 知识库=1切/xxx段`，
所以**报告里现在能直接看出索引是新是旧** —— 下一个报告我不用再猜。

## 三、媒体端口模型不再进「会话模型面板」

### 3.1 与 0.66 那个 400 是**同一条链路**

Agnes 的图像 / 视频模型是**内置端口**（走 `/images/generations` 与 `/videos`），
拿去打 `/chat/completions` **必然 400**。

* **写入侧**（设置页）：早就过滤了；
* **读取侧**：**原来不过滤** → 老版本写进去的残留、或用户手填的条目，
  会一直留在「会话模型面板」里 → **选中就是 400**。

0.66 修「影视·提示词专家 400」时，我在注释里承认过这个洞
（"清单里已经存在的媒体模型管不着"），但**只修了"提示词专家"这一个使用点**，
没修"读取配置 / 写会话配置"这条路 —— 这次补上。

### 3.2 修法：规则下沉 + 一个点管全部

```
data/media_port_rule.dart   ← 新（叶子文件，**故意不 import 任何东西**）
data/agnes_builtin.dart     ← 改成"引用"那几个常量（值仍然只有一份）
data/chat_model_rule.dart   ← 委托给同一份判定
data/configured_models.dart ← readConfig 里统一过滤
```

**为什么要新开一个文件**：规则现在要在**数据层**也用，而 `agnes_builtin.dart`
因为要用 `ConfiguredModels.envNameFor`，**反过来 import 了 `configured_models.dart`**
—— 规则留在那边就成环。

**为什么滤在 `readConfig` 就够**：会话面板（`choices`）、写会话配置（`dsh_runtime`）、
诊断报告**全都读 `readConfig`**。滤一次，全部生效。
这种"漏一个入口就复发"的规则，**越少调用点越安全**。

顺带：如果 `selected` 正好指着被滤掉的媒体模型，也一并清掉
（否则界面会显示一个"当前模型"却哪儿都找不到它）。

## 四、MiniMax 视频档位：照官方文档，抓到两处错

你要求「顺便对一遍官方文档」。逐条核对
[创建视频生成任务（v2）](https://platform.minimax.cn/docs/api-reference/video-generation-v2-create)，
抓到**不止秒数**：

### 4.1 错一：时长范围是 v1 的旧口径

| | 我们原来写的 | 官方 v2 文档 |
|---|---|---|
| `MiniMax-H3` | 6–10 秒 | **4~15 秒** |
| `MiniMax-H3-Max` | （没区分） | **5~15 秒**（不支持 4 秒） |

原来的 6–10 是 v1 Hailuo 的口径，把合法的 4 秒和 11~15 秒全挡了。

### 4.2 错二（更隐蔽）：默认分辨率是 H3 **不支持**的一档

官方原文：

* `MiniMax-H3`：分辨率 `768P` / `2K`
* `MiniMax-H3-Max`：分辨率 `480P` / `768P`（不支持 `2K`）
* `resolution` 是**枚举**：`480P` / `768P` / `2K`

而界面的兜底档位取的是 `resolutions.first`，当时列表是 `['480P', '768P', '2K']`
→ **默认模型是 `MiniMax-H3`，一进这一页拿到的就是非法的 480P**。

修法：列表改成 `['768P', '480P', '2K']` —— **768P 是两个模型唯一都支持的那档**。

### 4.3 脚本侧再加一道兜底

`media-vendors.mjs` 的通用兜底分辨率是 `'720P'`（Agnes 与万相用），
但 MiniMax v2 的枚举里**没有 720P**。现在这一家收到非法值会兜成 `768P`，
并在日志里打印实际用的档位。

### 4.4 同一份文档核对过、**没有**问题的两条

* **文生视频时 `ratio` 必填且不能是 `adaptive`** —— 我们发的是具体比例（默认 `16:9`），✓
* **`content[]` 必须含一个非空 `text` 项** —— 0.65 已经修过 ✓

## 五、CC BY-SA 4.0 署名

这是**唯一未闭合的合规项**：那份语料是 CC BY-SA 4.0，该许可**要求署名**，
而界面上只写了「许可：CC BY-SA 4.0」—— 声明了许可，但**没署名**。

现在「关于」页版本号下面写着：

> 知识库内容来自第三方社区语料，依 CC BY-SA 4.0 许可使用。

**只说"第三方社区语料"，不点数据源名字** —— 与你 2026-10-12 那条
「把知识库的中文维基百科字样消除，就写知识库三个字就行」**不冲突**：
该保留的是**署名 + 许可**，该去掉的是**点名数据源**。
