## 2. 通道自检：从"只看清单"改成"真打一次对话"（用户第 ② 句的隐含要求）

**问题**：自检原来只对 zen 打 `GET /inference/v1/models`。而 1.2 已经证明**清单一律 200** ——
于是"这条通道根本用不了"会被报成**"这条通道是好的"**。**假通过比不报还坏**。

**改法**（`app/lib/local/channel_selfcheck.dart`）：

1. zen 那条改走**本机代理**（与 App 真正用的路径完全同一条）发一次 `max_tokens: 1` 的对话；
2. **最多试 3 个**免费模型（因为地区封锁是**按模型**的：只试一个会把"这个模型不许用"
   误报成"整条通道坏了"）；第一个 200 就算通；
3. 403 拆成两种结论：`blocked`（门禁：非官方客户端）与新增的 **`region`（地区封锁）**
   —— 两者的"下一步"完全不同（换模型 vs 换网络）；
4. 代理没在跑 → 报 `network` 并给"回设置把它打开一次"的具体动作，而不是含糊的"失败"。

**隐私口径**（界面文案同步改了）：普通厂家仍是只读 `GET`；免 Key 那条会**真发一句话**
（1 个 token），但**只打 127.0.0.1**、不带任何凭据、不写文件、不上传结果。
原话"各通道只发一次最小的读取请求：不写任何东西、不上传任何内容"**不再成立**，
改成「只发最小的探测请求（免 Key 那条会真发一句话，1 个字）…」—— 这一条是**刻意**改的：
宁可把话说准，也不要留一句跟行为不符的承诺。

**顺带修一个 i18n 洞**：整块自检（标题 / 10 种结论 label / 下一步 / 详情）原来用的是
**裸中文字面量**，一条都没进翻译表 —— 外语界面下这一页全是中文。现在全部 `tr('…')`
并补齐三语；`i18n` 从 1846 → **1883** 条（含删掉的 3 条陈旧），`check-tables` 三语 0 漂移。

## 3. PPT 排版层：用 node 重写（本轮主件，用户第 ① 句）

### 3.1 之前是什么、为什么不够

老 `make-pptx.mjs` 只会**两种版式**（封面 / 标题+项目符号），位置尺寸靠**占位符继承**：
模型给什么就画什么。三个后果：内容一多就**溢出**（PPT 打开不重排）；想画卡片/时间线/对比
就得让模型自己算 EMU 坐标（它算不准，每次还不一样）；完全没有设计。

### 3.2 分成两层（可测、确定性）

| 文件 | 职责 |
|---|---|
| **新** `app/assets/toolbox/pptx-design.mjs` | **只算**：主题配色、文本测量、自动缩排/分页、12 种版式的形状树。纯函数 —— 能直接 `import` 进来单测（就为这个才拆出来的） |
| `make-pptx.mjs`（改） | 打包：ZIP + OOXML + rels + 图片 media + 备注 + 转场，以及**分页决策**（要在渲染前做，页码才对得上） |

### 3.3 12 种版式（模型只写内容 + 选版式，坐标全由引擎算）

`cover` 封面 · `section` 章节页 · `toc` 目录 · `bullets` 要点 · `cards` 卡片 ·
`timeline` 时间线 · `compare` 两栏对比 · `metrics` 大数字 · `chart` 数据图
（`bar` / `hbar` / `stacked`）· `quote` 引用 · `image` 配图 · `end` 结尾。
不写 `layout` 时按内容字段**自动推断**（`items`→cards、`steps`→timeline…），所以**v1 老大纲
一字不改继续可用**（有测试）。

### 3.4 排版的四件事（都是"能验证的规则"，不是感觉）

1. **文本测量**：CJK 1 em / 拉丁 ~0.53 em / 空格 0.28 em → 估算行数。
   ⚠️ 故意**宁可高估行数**（字号偏小）也不让它溢出。
2. **自动缩排**：字号阶梯 18→9.5pt；要点页的**可读下限是 12pt**（低于它不缩了，去分页）。
3. **自动分页**：要点页放不下就拆**续页**（标题带「（续）」），按高度找"能放下的最大前缀"；
   **单条本身超长**（模型把一整篇文章塞成一条要点）时把这一条**切段**接着排，一个字不丢。
4. **单块文字收缩**：封面/章节/结尾标题、卡片标题与正文、引用都按自己的框收缩
   —— 否则一个 50 字的封面标题会压到副标题上（这是本轮自测抓到的真问题，见 3.6）。

### 3.5 设计层

6 套主题（`ink`/`ocean`/`forest`/`sunrise`/`berry`/`mono`，各 5 档色）；
标题左侧强调条 + 眉题 + 页脚/页码（**封面/章节页/引用页/结尾页不画页码**）；
行内 `**粗体**` 会变成**真的加粗**（不处理就会把两个星号印在 PPT 上）；
可选换页转场（`fade`/`push`/`wipe`/`cover`/`zoom`）；图片按原比例等比放进框（不拉伸）、
找不到图就画占位并给警告、同一张图用多次只存一份。

### 3.6 本轮自测抓到的三个真问题（都会影响成品）

1. **`text` 与 `paras` 用混**：我一开始把"已经拼好的段落 XML"当普通字符串塞进 `text`，
   于是它被**又转义了一遍** —— 结构校验全绿，幻灯片上却显示一坨 `<a:p>`。
   修法：`shape()` 明确区分 `text`（原始文字，会转义）与 `paras`（拼好的 XML）；
   并且**在结构校验里加一条硬断言**：正文里出现 `<a:p` 就是失败。
2. **`fitSingle` 的条件写成了 `||`**：只要"行数 ≤ 上限"就认为放得下，
   于是一个 50 字的封面标题按 40pt 原样输出、压到了副标题上。改成 `&&`（高度与行数都要满足）。
3. **0×0 的"空组"形状**：`spTree` 里的 `grpSpPr` 本身就是 0×0，它让"越界/零尺寸"检查
   误报每页都有问题。测试里先把 `<p:grpSpPr>` 摘掉再判。

### 3.7 验证（两层，共 32 条）

```sh
node install/test-make-pptx.mjs          # 25 项：容器层 / 排版层 / 设计层 / 容错
flutter test --no-pub test/office_pptx_test.dart   # 7 项：真生成 + 系统 unzip -t + 抽事实断言
```

| 层 | 断言要点 |
|---|---|
| ① 容器 | 每段 XML 良构（自写的无依赖校验器）、**每个关系都有目标**、`[Content_Types].xml` **覆盖每个部件**、形状不越界、**除文档属性外两次生成逐字节一致** |
| ② 排版 | 内容越多字号越小（单调）、拆页后条目**恰好出现一次**、续页标题带后缀、正文字号不低于 12pt、卡片 6 条 = 3 列 2 行 |
| ③ 设计 | 6 套主题的强调色真的写进 XML、页码不在封面/章节页、版式推断、备注进 notesSlide、图片 `blip` 的 rId 在 rels 里对得上、同一张图只存一份 |
| ④ 容错 | `slides` 不是数组 / `bullets` 是数字 / `layout` 写错 / 空页 / **单条 5000 字** → 都有兜底且不崩 |

另有**独立第三方校验**：Dart 测试里用**系统 `unzip -t`** 判定容器（不听我们自己写的 ZIP 读取器）。

### 3.8 边界（如实写，也要让模型如实说）

* 数据图是**形状画的**（柱/条/堆叠 + 数值标签）：能改颜色尺寸、一眼看懂，
  **但不是** OOXML 图表对象 —— 数据改了要重新生成。
* **没有**逐元素动画与音频嵌入；**只有**换页转场。
* 图片只吃**本地文件**（png/jpg/jpeg/gif/bmp，单张 ≤16MB），**不联网抓图**。
* 排版是按**字符宽度估算**的（离线、无字体文件）：换了字体可能一行多/少一个字。
  所以缩排只往小里选、留了 `<a:normAutofit/>` 让 PowerPoint 自己还能再缩一档兜底。
* `slate`（淡紫）/`sand`（沙色）这类主题名**不给**：给了 12 个名字但只做 6 套，
  模型会写出"看起来支持、实际回落到 ink"的假象。

## 4. 顺手修好的存量红灯：`atomic_file_test.dart`

今天早些时候的提交（`4fc297f` 「修掉日志里暴露的三个真问题」）把原子写的临时文件名从固定的
`<目标>.part` 改成**带唯一后缀**（真机上两次保存相隔 21ms 撞同一个 `.part`，
先完成的把它 rename 走，后一个直接失败、**那次更新就丢了**）。

**但测试没跟着改**：它还在断言"盘上没有那个固定名 `.part`" —— 新实现当然不会再创建这个名字，
于是那条断言**变成了永远为真**（等于没验），而"手工造一个 `.part` 再写一次"那条则**直接变红**。

改法：断言改成"盘上**没有任何 `.part*` 残留**"，并**补一条并发测试**
（同时写三次，目标必须是其中一次的完整内容、且不留临时文件）—— 把当初那个真实的丢更新
变成回归测试。该文件 17 项全过。

### 7.1 这次出包抓到的两个真问题（**都不是这一轮代码引入的**）

#### ① ffmpeg 那一套 10 个 `.so` 在 0.75 的**所有旧包**里都不见了

`install/check-release.py` 直接判 FAIL（`MUST_SHIP_EXEC_SO` 那 10 项）：

```
[FAIL] 引擎检查：运行时 dlopen 的库必须都在
       缺了：libffmpeg.so / libffprobe.so / libavcodec.so / …（共 10 个）
```

| 事实 | 证据 |
|---|---|
| 0.74 的发布包**有**这 10 个 | `unzip -l dist/paopaocat-preview-0.74-…apk`：libavcodec.so 14,087,760 … |
| `20261015a`~`h`（以及我第一遍出的 0.75）**一个都没有** | 同一命令只列出 18 个 lib，全是 node/termux/onnx/sherpa |
| 它们的来源不是 Maven、不在 `libapp.so` 里 | 它们由 `install/build-ffmpeg-android.sh` 编好后落进**构建目录**（`$DSH_ANDROID_NODE/jnilibs`） |
| 构建目录在 **10-16 02:49** 被重建过 | `/tmp/dshbuild/android-node/jnilibs/arm64-v8a/*.so` 全是那个时间戳，且里面**没有** ffmpeg |

**后果（真机上）**：点「口播 / 短剧 / 剪辑 / 配音」会 `ENOENT` —— 编译期毫无征兆、
`flutter test` 照过、`libapp.so` 里的字符串全在（因为那几个脚本还在包里）。
这正是 `check-release.py` 存在的理由：**它只认包里的字节**。

**修法**：从 **0.74 的发布包**里取回同一批字节（10 个文件，size 与 ELF 头逐一核对），
放进构建目录**并且**在 `__migr/03-build-deps/android-node/jnilibs/` 留一份持久副本 ——
以后 `/tmp` 被清、re-跑 `fetch-termux-deps` 时不会再丢。重新出包后该检查项 PASS。

> 想要"更正统"的来源：跑 `install/build-ffmpeg-android.sh`（需要 NDK + ffmpeg 源码 + x264 +
> patchelf，产物默认落 `/tmp/ffshared-out`）。这次没走它，因为目标只是补回**已经发布过的那批字节**，
> 从发布包里取回更可核（size/ELF 都能对上），也更快。

#### ② 出包核对脚本对 LiteRT 四件套**假红**

`MUST_SHIP_LIBS` 要求 `liblitertlm_jni.so` / `libLiteRtClGlAccelerator.so` /
`libLiteRtCompilerPlugin_Qualcomm.so` / `libLiteRtDispatch_Qualcomm.so` 必须在包里，
而 `build.gradle.kts` 的 `packaging.jniLibs.excludes` **明确排除**了这 4 个 ——
理由是 **2026-10-14 用户原话「本地模型那一套彻底不用了」**（changelog 里也对用户写了
"本地大模型那一套整个拿掉了"）。于是每一次 0.75 出包都 FAIL，而**假红和假绿一样有害**：
看多了就没人再看这一项。

**修法**：把这 4 项从 `MUST_SHIP_LIBS` 移进 `PARKED_ENGINE_LIBS`（只报信息、不算失败），
并在两边都写清"要恢复只需删掉 gradle 里那四行 `excludes`"。
