## 修好「历史会话点开是空的」

**之前的问题**：点开一条历史会话，里面**一条内容都没有**，看着像对话被删了。

实际查下来（对话记录一个都没丢）——**磁盘上没有删过任何会话**；"空"是 App 自己造出来的：
你**只是点开过聊天页、或者从首页点了「内置会话」但没发出去**，App 就已经先把会话建到磁盘上了，
于是列表里堆了一批「没标题、点开全空」的空壳，把真正聊过的对话淹掉了。

**现在**：

* **只点开、没发消息，就不再往磁盘上落会话** —— 会话改成"你发出第一句话时才创建"；
* 列表里**不再显示一条消息都没有的会话**（判据是"里面到底有没有你说过的话"），
  并在「工作区 → 会话」那行如实写出"磁盘历史会话 N 条（其中 M 条是空会话，没列出来）"，
  免得你数一遍发现对不上、又以为在丢；
* 那些已经攒下的空壳**没有被删**（删你目录里的东西是不可逆的，这版不做这个动作）——
  它们只是不再出现在列表里。想清掉的话，路径在技术文档里，可以手动删。

> 已核对：48 个会话目录里 17 个是这样来的；**聊过天的会话一条都没被掏空**
> （全部 1187 个数据帧都能干净读出来，0 个损坏）。

## 切模型不再"偷偷换一个会话"

**之前的问题**：在一个会话里切模型，界面提示「会话内切换模型成功（会话未重建）」——
**这句话是假的**：紧接着进程重启、App 开了**另一个新会话**，你刚才那条提问就留在了旧会话里，
你在这边等不到回答。

**现在**：切模型之后**不管走哪条路重建，都恢复同一个会话**（不再换新 ID）——
App 会把"我正在用哪个会话"记下来，进程重启后用它接着来。
同一条链路上还有个顺带修掉的地方：**还没开始对话就切模型**时，不再说"正在重建会话"
（那时根本没有会话可重建），而是如实说"还没开始对话，正在按新模型准备会话"。

> 注：这一版仍然可能因为"模型配置变了"（改 Key / 端点 / 模型清单）而重启进程 ——
> 那是必须的（进程里的旧配置不会热更新），但现在重启**不会再换会话**。

## 提问失败时，会话里能看到原因

**之前的问题**：提问失败（上游连不上、被限流、协议不支持……）**只写在诊断日志里**，
会话本身**一个字都不记**。过一会儿回头看那条会话，只有你发出去的话，没有回答、
也没有任何报错 —— 很难不怀疑"我的对话丢了"。

**现在**：失败原因 App 会**自己记一份**；重新打开那条会话回看历史时，
末尾会出现一条**红色的「没有回答」**，写着人话原因（需要技术细节也能看到原始报错）。

> 如实说明：这条记录是 App 自己存的，**不在 DSH 的会话文件里**（那个文件由运行环境写，
> 它目前不会记录失败）。做到"会话文件本身就有错误事件"要改运行环境那一层，
> 这版还没做 —— 所以**换设备/重装 App 之后，这些失败提示会没有**（对话本身不会丢）。

## 连点发送不再白丢一轮

**之前的问题**：上一条还在回答时又发一条，会直接失败（`a prompt is already in flight`）。
日志里出现过 4 次，其中 2 次还紧跟在**请求超时**后面 —— 超时后状态没收尾，下一条就撞上了。

**现在**：请求**超时后会主动给运行环境发一条"取消"**把上一轮收尾，不再让它悬在半空；
另外"第一条消息要先把会话建起来"这段也加了防连点，不会因为连点而重复发。

## 还没做的（发版前要补齐）

* 真机验一遍：① 打开聊天页不发消息 → 磁盘上不该新增会话；② 切模型 → 会话 ID 不变、
  上下文还在；③ 断网发一条 → 回看能看到「没有回答 + 原因」；④ 超时后再发 → 不再报
  `a prompt is already in flight`。

  见 [`docs/CHANGES-2026-10-14.md`](CHANGES-2026-10-14.md) §6 —— 是否换出厂默认路由要你定。
