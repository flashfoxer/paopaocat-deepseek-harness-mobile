# 文档合写

> **来源**：本技能是**这个 App 自己写的**（没有改编任何上游技能）。
> 为什么不用现成的：Anthropic 官方开源技能库里那份 `doc-coauthoring` 我们**没有搬** ——
> 它的正文依赖 Claude 产品的概念（连接器 / artifacts），在手机上落不了地，而且那个技能
> 目录里**没有 LICENSE.txt**，许可不明（详情见 `docs/需求台账.md` 的 #82）。
> 这一份是按手机端真实能力重写的：**读得进来、写得出去、每一步都能给用户看**。

## 它解决什么

用户有一个"从零开始、要交出去"的东西：一份报告、一个方案、一段说明、一封正式的信、
一篇要发出去的长文。他不是让你**改一份已有的**（那是 `doc-processing` 的活），
而是**跟你一起把它写出来**。

最容易写坏的做法是：一口气糊两千字给用户，用户说"不是这个意思"，全篇作废。
所以这条技能的核心不是"写得多好"，而是**分步对齐**。

## 本机能力（先确认再动手，别假设）

* **能读**：`.md` / `.txt` / `.csv` / `.json` / `.html` / 源码；`.docx` 用
  `node "$DSH_ANDROID_TOOLBOX/read-docx.mjs" 材料.docx --out 材料.md`；`.xlsx` 同理用 `read-xlsx.mjs`。
* **能写**：Markdown 落盘；导出 `.docx` 用
  `node "$DSH_ANDROID_TOOLBOX/make-docx.mjs" 成稿.md 成稿.docx`（标题是真标题样式，
  Word 导航窗格能用）；表格用 `make-xlsx.mjs`；要 PPT 用 `make-pptx.mjs`。
* **没有** python / pandoc / Word / LibreOffice。要 `.pdf` 就给不出，如实说，替代是 `.docx` 或离线 HTML。

## 流程（五步，别跳）

### 1. 先问清四件事（一次问完，别挤牙膏）
* **给谁看**（领导 / 客户 / 同事 / 公开发布）—— 决定分寸与称谓。
* **要什么用**（批预算 / 讲清一个方案 / 交作业 / 存档备查）—— 决定重点。
* **多长**（一页纸 / 三页 / 不限）—— 决定取舍，宁短勿长。
* **什么形式**（Markdown 先看，还是要 `.docx`）。

用户要是**已经说清了**就别重复问；只补问缺的那一两项。

### 2. 出**大纲**让用户点头（这一步最省事）
给 3–7 个一级标题，每个后面**一句话**说明这一段要讲什么。
明确说："先看结构，结构对了我再往下写。" 用户改结构只要一分钟，改两千字要半小时。

### 3. 一段一段写，写完就停
* **一轮只写一到两节**，写完就把这一节给用户看，并**问一个具体问题**
  （"第二段的数字要不要换成上季度的？"），而不是笼统的"你看行吗"。
* 需要用户提供的事实（数字、日期、人名、金额）**列出来一起问**，不要自己编一个填进去。

### 4. 写的时候守住这几条
* **先给结论**：每节第一句就是那节的结论，后面才是理由。
* **具体压过漂亮**：写"3 月 12 日上线，晚了两周"，不写"取得了阶段性成果"。
* **别写 AI 味**：不要排比三连、不要"首先其次最后"、不要每段都首尾呼应、
  不要"赋能/闭环/抓手"这类词。一句里别塞两个以上的形容词。
* **保留用户的口吻与用词**：他习惯叫"咱们"就别改成"本公司"；
  他给的原话能用就原样用。**改动他的原话时要说一句**。
* **不确定就标注**：写"[待确认：Q3 具体数字]"比瞎写一个强。

### 5. 定稿与交付
* 落盘成 `成稿-<什么文档>.md`；用户要 `.docx` 就再导出一次（**先导出再报成功**，
  报之前确认文件真的在、多大）。
* 回复里给：**产物路径原样** + 这一版改了什么 + **还没落实的地方**（谁需要补什么）。
* 长文档别把全文贴进对话（用户手机上看不动）—— 给"结构 + 关键段落"，全文在文件里。

## 诚实边界
* **不替用户编事实**：数字、引用、承诺、法律条款，没有来源就不写；用户给的来源要说清"依据是你给的材料"。
* **不替用户拍板**：涉及对外承诺、金额、人事的表述，写成待用户确认的版本。
* **不假装**：导出失败、命令报错、文件读不到，如实说并给下一步（而不是说"已完成"）。
* 用户中途说"先这样"就**停在那里**，别自己接着往下写完。
