## 一、知识库「答得乱七八糟」的**第二个**根因

0.65（#64）修的是**切片**：以前不按文档边界切，一块里塞 9 篇无关文章。
这一版修的是**门槛**：切片修好之后，检索**还是**会把不相关的段当成"查到了"。

### 1.1 根因：入选条件只有「至少共享一个二元词」

`KbRetriever.search` 的老条件是 `overlap > 0` —— 只要和问题**共享一个**中文二元词就算命中。
问题在于「怎么 / 可以 / 什么 / 这个 / 我们」这类二元词**几乎任何 600 字段落里都有**。

所以对知识库那种 **25 万段**的语料：

* 随便问什么都能凑出 2 段语义不相关的资料；
* 调用方把这 2 段当成"知识库查到的"塞进上下文；
* 而提示词写的是「**请优先依据它们回答**；资料里没提到的不要编造，直接说不确定」——
  这是**无条件命令**。

三件事叠起来，模型只能拿两段无关材料硬编 —— 那就是你看到的"乱七八糟"。
换句话说：**问题不在"没检索到"，而在"检索到了错的东西、还被命令必须用"。**

### 1.2 口径是**量出来**的，不是拍脑袋

你批准方案时明确要求「用合成语料探针先量出来」。做法：造一份 **40 篇无关语料 + 1 篇相关**
的合成库（模拟"大语料里绝大多数内容都无关"这个真实形态），然后实测分数分布：

| 问句 | 结果 |
|---|---|
| 「晋城是什么」 | 相关段 **2 分**，随机段 **1 分** |
| 「晋城市下辖哪些县」 | 相关段 **2 分**，随机段（城市供水）**1 分** |
| 「光合作用是什么」 | 相关段 **4 分** |
| 「红烧肉怎么做」 | **0 段**（连候选都没有） |
| 「今天晚饭吃什么」 | **0 段** |

**分布非常干净：相关段 2~4 分，随机段一律 1 分。** 门槛就建在这条实测边界上。

### 1.3 门槛的两层口径

* **绝对层**：大语料（≥ 200 段）要求**两个词**同时对得上（`score >= 2`）。
* **相对层**：达不到最好那一段 **2/3** 分数的，是"顺带沾上"的尾巴，丢掉。
* **都过不了 → 返回空 → 不注入**，让模型按自己知道的答。
  这比硬塞两段无关材料诚实得多。

**小语料刻意不改口径**（这是这次最重要的一个保守决定）：
在 **3 段**的语料里，"共享一个二元词"**本身就是强证据**（别的段是 0 分）——
用户自己导入的笔记正是这种形态。所以门槛**跟语料规模挂钩**：

```dart
const int _kBigCorpusChunks = 200;   // 超过就算"大语料"
final need = chunkCount >= _kBigCorpusChunks ? 2 : 1;
```

不这么做的话，修好知识库的代价就是**把用户自己的笔记查不到**——那是拿一个问题换另一个问题。

### 1.4 措辞改成**条件式**

`formatKbContext`（用户消息里的材料）与 `localChatSystemPrompt`（system 位）都改了：

| | 改之前 | 改之后 |
|---|---|---|
| 口径 | 「请优先依据它们回答」 | 「它**可能**和问题有关，也可能完全无关」 |
| 相关时 | （同上） | 「优先依据它回答，它没提到的不要编造」 |
| 无关时 | （**没有这个选项**） | 「**直接忽略它**，按你自己知道的回答，不要被它带偏」 |

关键是**给出"忽略"这个选项**，并把"忽略"写成**正常做法** ——
小模型宁可硬凑，也不肯主动说"这段资料用不上"。

### 1.5 诊断日志补字段（**这条是防止我再误读**）

以前只记：

```
[dsh-kb] 注入 2 段 / 1226 字 ≈ 858 token（1 包参与，耗时 180ms）
```

这个数字对"答得乱"**完全没有解释力** —— 1000 字的无关材料也是 1000 字。
而且**我上一轮就是被它骗了**：把「注入 2 段」读成"包里只有 2 段"，
实际那是**每包上限 2 段**（`hits.take(2)`），25 万段的包里段数很多。
当时报告里没有 `chunkMode`，我根本没法纠正这个误读。

现在改成（新增三段信息，全部加粗的部分是新的）：

```
[dsh-kb] 注入 2 段 / 1226 字 ≈ 858 token（1 包参与，耗时 180ms）
  | 切法 知识库=2切/254547段（2=按文档边界，1=旧切法）
  | 分数 6,4
  | 摘要 晋城是山西省下辖的地级市，古称泽州，下辖… ‖ 太行山位于…
```

门槛没过时明确写：

```
[dsh-kb] 没有够相关的资料（相关度门槛没过）→ 不注入，模型按自己知道的答
```

**下一个报告我就能直接判断"查到的到底相不相关"，不用再猜。**

### 1.6 测试

`test/kb_index_test.dart` 新增「相关度门槛」组 5 例，用 **241 段**合成库
（超过 200 的阈值，走大语料口径）：

1. 无关问句 → **一段都不给**（不再硬塞 2 段）；
2. 相关问句 → 命中正确那段，且分数 ≥ 2；
3. 「2 分相关段 + 1 分随机段」→ 随机尾巴**必须**被砍掉；
4. **小语料口径不变** → 用户自己导入的笔记不许被大语料门槛连坐；
5. 措辞必须是**条件式**的（读源码断言，防回归）。

## 二、轮换池不再收本机模型

### 2.1 这条**推翻了更早的一个要求**

旧代码在轮换池的候选列表里**专门**给本机模型留了一行，注释写着
「用户明确要求『能把它加进池子』」；`model_sheet` 里还有一段专门把池子里的
`local/xxx` 显示成「本机」的逻辑。所以这次不是"加个过滤"，是**改口径**。

### 2.2 做法：三处都改，**并且收拾老配置**

1. 候选列表删掉本机模型那一行；
2. `_poolTapModel` 入口再挡一道（成员行的上移/下移也走它），
   误触时明说「本机模型只在手机上跑，轮换池是给云端模型排队用的」；
3. 落盘前**再滤一次**，任何路径都不许把本机模型写进池子。

**只删候选行是不够的** —— 老用户的池子里可能**已经**躺着本机成员，
池子照样会去试它，用户看到的就是"改了没用"。所以：

4. **打开模型设置页时做一次迁移**：把已有池子里的本机成员**真的移出去**
   （剔空的池子整个删掉，语义与既有的 `_pruneGroups` 一致），
   并在轮换池板块顶部**如实写出动了哪几个池子** —— 改了用户的配置不能悄悄改。

### 2.3 顺手修掉一个"测试全绿、用户说没改"的坑

迁移在 `initState` 里落盘，而 `await writeAsString` 在 `flutter test` 的
fake-async 区里**永不返回** → 迁移在测试里静默不执行，只有真机才生效。

修法：新增 `ConfiguredModels.saveConfigSync`（**同步**写，与异步版共用同一个
`_payloadOf`，防两边漂），迁移改走同步写。`models.json` 只有几 KB，
同步写一次的开销可以忽略。

### 2.4 测试

`test/model_panel_flow_test.dart` 新增 3 例：

1. 老池子里的本机成员**真的被移出去，并落盘**（且界面必须说出来）；
2. 整个池子只剩本机模型 → **池子一起删掉**，且 `selected` 不许指向死池子；
3. 候选入口防回归。

## 三、影视·提示词专家报 400

### 3.1 根因：它**拿错了模型**（你怀疑的方向是对的）

`prompt_expert.dart` 原来的 `_pickModel` 取 `models.json` 里**第一条**有地址、
有凭据的模型，直接 POST 到 `{baseUrl}/chat/completions`。两件事都不对：

1. **完全无视 `selected`** —— 你在会话里选的那个它不看；
2. **不过滤 Agnes 的内置图像/视频模型** —— 那两个模型挂在
   `/images/generations` 与 `/videos`，拿去打对话接口**必然 400**。

而"别用图像/视频模型"这个判断当时**只写在设置面板里**（只挡"写进去"，
挡不住"用起来"），再加上内置厂家顺序把 **agnes 排第一** → 稳定复现你说的 400。

顺带核实了端点是真的：`POST https://api.agnes-ai.cn/v1/chat/completions`
返回 **401「无效的令牌」** —— 说明鉴权在模型校验**之前**，
所以 400 只可能来自模型/参数问题，而不是"没接文本模型"。

### 3.2 做法

1. 判断抽成**唯一一份** `data/chat_model_rule.dart`（`isChatModelFor` +
   `isOpenAiCompatible`），设置面板与提示词专家**都调它** ——
   两边各写一份就是等着跑偏；
2. `expandPrompt` 改成**候选链**：先试 `selected`（`rotate/*` 是组名、
   不是模型名，跳过）→ 再按 `models.json` 顺序，**最多试 3 个**，
   只在 **400 / 404 / 422** 时换下一个（429 / 401 换也没用）;
3. **报错必须点名是哪个模型、打到哪个主机**：
   `模型返回 HTTP 400（用的是 agnes-image-2.5-flash @ api.agnes-ai.cn）：…`
   —— 以前只说"HTTP 400"，你就是因为这个才只能猜"没接文本模型"；
4. 试过多个仍失败时写清「已依次试过 N 个模型」。

### 3.3 测试

`test/prompt_expert_model_pick_test.dart`（新增 10 例，3 组）：
规则单元测试（含未来的 `agnes-image-3`）、真发 HTTP 到本地假上游
（**图像模型一个请求都不许发**、组名不许当模型名发、只有媒介模型时报
「还没有可用的云端模型」且零请求）、降级链（首个 400 → 第二个成功；
全 400 → 报错必须带模型名 + 主机 + 试了几个；429 **不**降级）。
